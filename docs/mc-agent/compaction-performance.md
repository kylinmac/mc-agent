# 会话压缩耗时与配置生效提示

2026-10-30 用户确认实施。需求 R20；会话页面 P8；验收 V59。

## 已确定

| 范围 | 契约 |
| --- | --- |
| 摘要目标 | 生成继续当前工作的交接摘要。篇幅上限取生成预算的 40%，最多 8K tokens，提示为上限一半到上限的区间（预算充足时即 4K–8K）；分割回合的前缀摘要上限 2K。短会话无需凑满。提示本次生成预算，小预算优先完成关键交接。篇幅是软目标，不通过截断摘要或删除未总结消息达标 |
| 截断处理 | 被输出上限截断的结果不落盘。先以减半的篇幅目标、模型最低支持推理等级（省略推理保持省略）重试一次，并以重试阶段显示；仍截断才按失败处理。两次用量合计记入检查点；用户停止后不再重试 |
| 必须保留 | 用户目标与修正、约束与授权边界、关键决策及原因、未完成工作与阻塞、必要路径／标识符／错误、测试结果和未验证项；压缩过时的过程细节和重复的已完成项 |
| 用户原话 | 仍有效的约束、禁止、批准／拒绝和纠正逐字引用关键句（每条约 300 字符内）；更新摘要时保留旧摘要中的引用，除非用户已撤销。已完成请求改写为结果；粘贴的日志、代码、长文档不照抄，只记内容、关键行与来源；引用合计约不超过摘要四分之一 |
| 推理策略 | 使用当前模型，摘要推理优先不高于 medium；不支持 medium 时向下选，只有更高等级可用时用模型最低支持级别。用户已有更低等级或关闭／省略推理时沿用其意图和既有能力映射。正常任务努力程度不变 |
| 超时保护 | 摘要请求接入流式静默保护；重试前取消旧请求；用户停止立即取消；定时器和监听在结束时清理。失败仍沿用手动报错／自动保留近期上下文的既有恢复语义 |
| 等待边界 | 静默预算沿用现有配置（默认 180 秒），不是摘要总时长上限。手动压缩 RPC 不再用错误的 744 秒总计时提前报失败；由流式保护、用户停止和进程关闭负责结束 |
| 进度 | 压缩显示等待模型、生成摘要、重试及独立耗时；不展示私有正文或内部推理内容 |
| 努力程度 | 运行中修改模型／努力程度继续排队生效，界面明确提示本轮结束后生效；成功、失败、切换会话均正确清理或保留对应提示 |
| 兼容 | 不修改已保存会话，不改变权限。Codex 路径不盲目添加不支持的输出上限参数 |

## 已观察事实

安装版 1.0.31 的一次压缩从请求发出到摘要落盘耗时 11 分 16 秒；输出 17,014 tokens，摘要 53,419 字符，上一次摘要为 32,533 字符。旧提示词要求累计保留旧摘要全部信息；摘要继承会话推理等级；Codex 请求没有发送输出上限；压缩没有使用普通对话的流式静默保护。日志不足以拆分网络等待和模型生成耗时。

## 验证计划

- 用可控模型流覆盖静默、持续输出、瞬时失败重试、用户停止、取消与结束竞态，检查请求取消和资源释放。
- 检查摘要策略适配不同推理能力，失败或截断输出不写成成功摘要；不删掉原始历史。
- 用本地假模型覆盖自动／手动压缩与 UI 的待生效、进度、独立计时路径。
- 不调用真实付费模型，不操作用户正在使用的安装版；模型摘要的语义保真与实际加速幅度仍需后续真实会话验证。

### 2026-10-30 预算与截断修正（B-039、B-040）

复查发现：固定 4K–8K 目标在 8K 输出上限的模型上与推理共用预算，容易截断；截断不属于瞬时错误，pi-ai 不重试，于是每次压缩都失败，自动路径丢掉整段旧历史。分割回合的前缀请求还会沿用上一请求的尝试次数。

| 检查 | 实际结果 |
| --- | --- |
| 摘要模块 | 新增 8K 预算目标缩放、前缀短目标、截断后一次短重试（推理降级、用量合计、回调通知）、停止后不重试、用户原话规则用例 |
| runtime | 分割回合前缀请求从第 1 次计数；撤掉修复时该用例失败 |
| agent-runtime 完整测试 | 112 个文件、1535 项通过；类型检查、`pnpm lint` 通过 |

篇幅比例 40% 与原话规则依据参考实现和推算，未用真实模型量过截断率与摘要保真。
