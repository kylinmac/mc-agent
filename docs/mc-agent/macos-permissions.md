# macOS 权限归属与授权体验改造

**日期：2026-10-22。状态：已按本文建议实施（[MC-ADR-0015](adr/mc-0015-macos-permissions.md)），结果见第 9 节；下文第 1–8 节保留评审原文。**

本文区分代码事实、平台规则和待验证假设。目标是让用户知道“给谁开、为什么开、在哪开、开完是否有效”，减少误授权和重复操作。本文使用 X-PERM 临时提案编号；开发前将已确认内容同步正式需求 R、页面 P、验收 V，以及 MC-ADR-0008／0014 或新的 ADR。不能仅凭本文认定已批准改变进程或发布架构。

## 1. 结论

分两条线改造：**先稳定应用与辅助进程身份，再提供按功能引导的权限页面。** 只增加“打开系统设置”按钮不能解决授权归属错误；只改 bundle ID 也不能保证授权自动出现或升级后保留。

macOS 权限不绑定聊天中的某个 Agent、会话或模型。系统会判断执行敏感操作的代码及其负责应用；辅助进程是否归属主应用，取决于实际启动和身份识别。应用内的工具审批、插件授权、macOS 系统授权是三层独立门槛，不能互相代替。Apple 对 responsible code 的说明见[应用不出现在隐私设置中的诊断](https://developer.apple.com/forums/thread/125438)。

建议最终体验：用户在 mc-agent 中按需点击一次“设置权限”，依次完成必要系统授权，回到应用后自动复检；界面显示本次应授权的应用名称和实际安装位置。系统允许的步骤由程序完成，系统要求的用户确认保留，不承诺“一键自动开权限”。

## 2. 当前实现与已经发现的问题

| 源码确认 | 影响 | 依据 |
|---|---|---|
| Computer Use 以插件声明的 `bin/mc-computer mcp` 独立 stdio 进程提供能力 | 不能只检查 Electron 进程权限后就宣布电脑操作可用，必须检查实际执行进程 | [manifest](../../apps/desktop/resources/plugins/mc.computer-use/manifest.json)、[构建脚本](../../scripts/build-mc-computer.mjs) |
| Rust helper 内调用 `AXIsProcessTrustedWithOptions`、`CGPreflightScreenCaptureAccess`、`CGRequestScreenCaptureAccess` | 系统授权调用来自 helper，实际 responsible app 尚未在签名安装包中验证 | [macOS 后端](../../crates/mc-computer/src/macos/mod.rs) |
| `permissions(request=true)` 同时请求辅助功能与录屏；缺辅助功能时打开其设置页，否则才打开录屏页 | 两种请求与一个设置页混在一次调用中，用户不易知道还缺哪一步 | 同上 |
| 设置页通过 `/usr/bin/open` 打开，返回状态被忽略；权限返回两个 bool 与文本 guidance | 打开失败没有清晰反馈；false 无法可靠区分未申请、拒绝或系统限制 | 同上、[Permissions](../../crates/mc-computer/src/backend.rs) |
| 引导文本硬编码 mc-agent、PI-Desktop 或 Electron；旧方案断言授权对象必定是启动应用 | 用户可能被引导开启错误条目；不能将预期归属当作已验证事实 | 同上、[原电脑操作方案](computer-use.md) |
| 安装包 appId 为 `com.kylinmac.mc-agent`，productName 为 mc-agent；麦克风／本地网络用途说明仍写 PI-Desktop | 系统弹窗和应用名称不一致 | [打包配置](../../apps/desktop/package.json) |
| 开发启动脚本仍使用 `PI-Desktop` 和 `net.aiuo.pi-desktop.dev`，缓存位置含 Electron 版本／品牌哈希，使用 ad-hoc 签名 | 开发身份与安装身份不同，重建也可能影响权限识别；不能用开发版授权表现验收正式版 | [dev-electron.mjs](../../scripts/dev-electron.mjs) |
| mc-agent 专用发布脚本显式选择 ad-hoc 签名；继承的 release workflow 另有 Developer ID／公证流程 | 仓库有正式签名配置不代表当前分发包已使用；需要统一实际发布入口 | [mc-release.mjs](../../scripts/mc-release.mjs)、[release workflow](../../.github/workflows/release.yml) |
| 麦克风检查／请求在 Electron，插件音频还有独立授权检查 | 可以统一设置入口，但不能绕过插件或实时通话的既有权限判断 | [audio-backend.ts](../../apps/desktop/electron/main/audio-backend.ts)、[plugin-panel-host.ts](../../apps/desktop/electron/main/plugin-panel-host.ts)、[实时语音权限](../../apps/desktop/electron/main/live-voice/microphone-permissions.ts) |

**尚未确认用户当前故障的具体原因：** 没有检查正在使用的安装包、系统授权列表和启动链；不能断言是 helper 失去归属、旧签名残留，或某个权限尚未真正请求。以上是源码可定位的改造点，不是对当前机器的最终诊断。

## 3. 权限与功能对照

| 系统权限／门槛 | 使用场景 | 检查与请求位置 | 建议用户体验 |
|---|---|---|---|
| 辅助功能 | 读取应用元素、点击、输入和操作控件 | 实际 Computer Use helper 的 AX API | 首次启用电脑操作时解释用途，用户点击后单独请求；提供系统设置入口和当前应用定位 |
| 屏幕录制／屏幕与系统音频录制 | 获取其他应用窗口截图 | 实际截图执行进程的 CoreGraphics API | 需要截图时请求；未开启时保留现有可用的元素树能力，不将缺截图误报为所有能力失效 |
| 麦克风 | 语音通话、录音及已授权插件音频 | Electron 的媒体权限 API，沿用现有调用 | 用户开始语音或点击授权时请求；拒绝后引导设置，受管理限制时明确说明 |
| 文件与文件夹 | 读取系统保护位置中的项目／资料文件 | 实际读取进程及具体目标路径 | 遇到访问失败时说明路径和可能原因；不能把所有 EACCES／EPERM 都归为 TCC |
| 完全磁盘访问 | 特殊受保护数据访问，是否需要由具体功能决定 | 不存在本方案可依赖的统一公开授权状态查询 | 不作为日常项目管理或电脑操作前置要求；不拿此权限解决所有文件错误 |
| 自动化（Apple Events） | 将来若有向其他应用发送 Apple Events 的能力 | 按实际发送进程和目标应用处理 | 当前 AX 实现不因“控制其他应用”就要求此权限；新增相关能力时再设计 |
| 本地网络 | 访问局域网模型或服务 | 当前打包已声明用途，具体连通性走服务请求链路 | 本期可说明用途和故障入口；连接失败不直接标为“权限被拒绝” |
| 应用内工具／插件审批 | 允许某次动作或启用插件能力 | 既有 host-core／插件权限链路 | 与系统权限分开显示：系统已允许不等于当前工具已获准执行 |

不要为了“齐全”预先索要摄像头、输入监听、自动化或完全磁盘访问。AX 输入不等于全局输入监听需求。目录选择器也不代表用户授予了全盘权限。

Electron `askForMediaAccess` 只支持 microphone／camera，不能用它申请录屏；AX 查询针对当前进程，不能替代 helper 的检测。见 [Electron systemPreferences](https://www.electronjs.org/docs/latest/api/system-preferences)。系统录屏设置说明见 [Apple 用户指南](https://support.apple.com/en-gb/guide/mac-help/mchld6aa7d23/mac)。

## 4. X-PERM-01：稳定授权身份与启动链（先验证，再改架构）

### 4.1 第一阶段：保留现有独立 helper，验证主应用归属

1. 确认正式发布的唯一入口和签名策略。优先让正式分发使用稳定 bundle ID、Developer ID 签名和公证；没有证书时如实标为 ad-hoc 测试包，不承诺权限跨构建保留。签名、公证与系统授权是不同事项，公证不会替用户授权。
2. 检查完整启动链、实际 helper 路径和签名：是否从签名 app 内运行，还是被复制到可变插件目录后运行；是否经过 shell、终端或其他解释器；是否脱离主进程生命周期。读取 manifest 不能替代实际进程证据。
3. 确保内置 helper 纳入最终签名校验，并核查 Apple 推荐的嵌套代码位置。当前 helper 位于插件资源目录；是否迁至标准辅助可执行文件位置，依据签名和归属实验决定，迁移时同步 manifest 解析与打包，不只改复制脚本。
4. 从 Finder 启动已安装 app，分别触发 AX 和录屏请求，记录系统显示名称、授权后 helper 复检结果。主应用和 helper 检查不一致时显示异常，不向用户宣称已经可用。
5. 同签名身份构建升级包复测；固定路径只是稳定性措施之一，不是授权保证。Apple 的 designated requirement 用于识别代码身份，见 [TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)；嵌套代码位置与签名见 [TN2206](https://developer.apple.com/library/archive/technotes/tn2206/)。

**优先方案：** 保留 `mc-computer` 的隔离、MCP 协议与执行边界，先修正确的签名、打包、启动归属和引导。不要第一步就把 AX／截图实现搬入 Renderer，或给整个插件系统增加任意特权代理。

### 4.2 第二阶段：只有归属实验失败才考虑辅助应用

如果正式签名包在支持的系统上无法稳定归属主应用，再评估内置有固定身份的 `mc-agent Computer` 辅助应用／平台服务。其名字和所在位置必须可向用户解释；用户可能需要授权辅助应用，不能仍承诺系统只显示 mc-agent。

此方案须单独 ADR：明确生命周期、父子关系、认证、调用者校验和退出清理。若引入跨进程服务，只接受受验证的主应用和固定操作，不开放任意 shell／路径／脚本执行；不得用公开监听端口或未经认证的 IPC 继承系统授权。使用系统支持的启动方式，不采用私有 responsibility API 修改归属。

### 4.3 开发版单独处理

- 建议统一为清晰的 mc-agent Dev 名称及独立 bundle ID；发布版 ID 保持不变。
- 先检查 MC-ADR-0008、现有 userData／数据目录兼容；改开发包品牌不能顺带迁移或删除用户数据。
- 显示“开发版权限可能需要在重新构建后确认”；可提供稳定开发签名方案，但不把生产证书写入仓库。
- 不自动重置旧 PI-Desktop、Electron、Terminal 的授权，不把给 Terminal 开权限作为正式安装版的标准步骤。

## 5. X-PERM-02：按功能的权限设置与恢复流程

### 5.1 入口与页面

复用设置页，新增“系统权限”分区；电脑操作插件详情提供“检查权限”，语音失败提示链接到对应权限项。未启用电脑操作时不为了检测而偷偷启动其 MCP 服务；显示“启用后可检查”或仅显示应用身份信息。

每项展示：功能用途、当前检查结果、检查对象、下一步按钮。普通用户只需看到应用名、安装位置和短说明；签名、进程路径、bundle ID 放在可展开的诊断详情。

主要按钮为“授权”“打开系统设置”“重新检查”；仅在该设置页支持手动添加应用时提供“在访达显示应用”，并说明如何选择当前安装副本。深链接是便利入口，失败时显示手动导航路径，不承诺所有 macOS 版本都能直达或高亮某条记录。

### 5.2 用户路径

1. 首次点击使用电脑操作 → 检查插件启用状态及实际 helper 能力。
2. 缺辅助功能 → 显示用途，用户点击“设置辅助功能”后发出对应请求并打开设置。
3. 回到应用窗口 → 自动重新检查辅助功能；接下来只在需要截图时引导录屏，不同时弹两个请求。
4. 设置列表没有应用 → 显示实际 app 路径，确认已经从当前 app 发起请求；辅助功能可引导手动添加，其他权限按对应系统页能力处理。用户拒绝后不循环申请。
5. 权限开启后 → 先重新检测；必要时由用户触发重新连接电脑操作服务。重启 helper 会清空元素句柄与窗口索引，旧引用失效，下一次操作必须重新读取窗口状态。
6. 仍需重启主应用 → 清楚说明可能原因，先展示运行任务／后台命令／语音状态，再让用户主动重启；不能自动中断任务。系统已经可用则不要求多余重启。
7. 用户撤销权限 → 下一次能力检查／调用返回对应恢复提示，不不断自动重试动作，也不自动重放之前的点击、输入或文件操作。

页面只在可见或应用回到前台时复检，去重并限制频率；卸载和切换时清理监听，不常驻高频轮询。

### 5.3 状态契约

不要把全部权限压成一个 `authorized: boolean`。建议每项包含 `capability`、`state`、`checkedAt`、`checkedBy`、可执行的恢复动作和诊断原因；字段最终按现有 shared／IPC 习惯收敛。

- AX／CoreGraphics 仅返回布尔值时：使用“已允许／未获授权”，不能推断“从未请求”还是“用户拒绝”。
- 麦克风按系统返回保留 granted／denied／not-determined／restricted／unknown；当前音频封装将 restricted 合并为 denied，权限页面应保留更细状态或独立适配，避免破坏旧调用方。
- helper 未启动、请求超时、平台不支持、签名归属待确认分别展示，不能都变成“未授权”。
- `restartSuggested` 是恢复建议，不伪装成系统直接返回的权限状态；重启后重新检测。
- 不能读取全部 TCC 数据库来制造“全权限总览”；没有公开可靠查询的项如实显示未知或针对目标访问诊断。

## 6. X-PERM-03：具体开发落点

| 模块 | 最小修改 | 验证重点 |
|---|---|---|
| `crates/mc-computer/src/backend.rs`、`macos/mod.rs`、`tools.rs` | 增加指定权限的检查／请求；兼容旧 `permissions(request: bool)`，新 UI 使用分项请求；结构化返回可诊断错误，检查打开设置的退出结果 | 检查不弹窗；每次只请求所选权限；旧 MCP 调用不崩；非 macOS 明确不支持 |
| Electron Main 新增 macOS 权限模块及对应 IPC | 聚合音频与实际电脑操作服务状态；固定权限名、固定设置页目标、受信调用方；复用现有 MCP 服务管理，不另起一个可能归属不同的探测进程 | renderer 不能传任意 URL／命令／可执行路径；服务未启用不偷偷启动；请求超时、取消及并发处理 |
| Preload、shared、`src/lib/api.ts` | 增加有限的检查／请求／打开设置能力，保持运行时参数校验 | 生产者、消费者和类型同步；不暴露 Electron 原始对象 |
| `features/settings`、插件详情、语音提示、i18n | 权限分区、按功能引导、回前台复检、错误恢复；使用现有 UI primitives | 中英文、键盘操作、加载／错误态、清理订阅；无权限时不误禁其他功能 |
| `apps/desktop/package.json`、`build/entitlements.mac.plist` | 更正用途说明的品牌；按实际 API／最低支持系统检查需要的 Info.plist 项。核查主应用和 helper 的签名要求，不因权限故障增加宽泛 entitlement | 最终包的 plist 与签名检查；Hardened Runtime 不等于 App Sandbox，不盲加 `app-sandbox`／`inherit` |
| `scripts/build-mc-computer.mjs`、`scripts/mc-release.mjs`、`scripts/verify-macos-release.sh` | 统一正式发布策略，加入最终 helper 存在性、架构、签名和实际路径的校验；必要时调整标准打包位置 | 两次正式构建的 app／helper 身份一致；验证升级授权表现，不只验 codesign 成功 |
| `scripts/dev-electron.mjs`、安装身份模块 | 开发品牌与身份单独明确；不混用开发与发布数据 | 旧开发数据兼容；测试不触碰已安装 PI-Desktop／mc-agent |
| 电脑操作技能与方案 | 改成能力缺失时返回应用内引导，说明准确授权对象；保留既有动作审批 | 模型不反复调用 `request=true`，不建议给所有终端／解释器全盘权限 |

新权限入口不能成为跳过 host-core 动作审批的通道。仅检查权限可只读；弹系统提示、打开设置必须由用户明确操作或已明确请求设置该项权限触发。自动刷新不得携带 request=true。

## 7. 实施顺序与验收

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| P0 身份诊断 | 安装包与实际 helper 路径、签名、启动链记录；系统条目截图由隔离测试环境采集 | 能说明本构建的真实授权对象；明确当前症状是否重现，不将猜测写成结论 |
| P1 最小可用引导 | 品牌说明修正、分项请求、权限设置页、复检与错误恢复 | 未授权用户能完成辅助功能／录屏设置；不开全盘权限也能使用电脑操作 |
| P2 正式发布稳定性 | 选定并落地签名／打包／启动方案 | 同身份升级通过授权回归；多副本、开发版与发布版区分清楚 |
| P3 其他能力接入 | 麦克风统一入口、按需文件访问诊断 | 保留插件审批；受限与拒绝可区分；无通用 API 的状态不伪报 |

自动测试：模拟各权限返回、请求单项选择、IPC 参数白名单、打开设置失败、服务不可用、前台复检去重与监听释放、旧 MCP 参数兼容。Rust 用后端替身，UI／Main 用 API stub；不在 CI 自动点击系统授权。

手动验收必须覆盖：首次安装无条目、允许、拒绝、返回设置开启、运行中撤销、helper 重连、需要应用重启、多 app 副本、Finder 与终端启动差异、同签名身份升级、ad-hoc 开发重建、已启用工具审批仍生效、无录屏时元素树能力、无麦克风时文本聊天不受影响。覆盖最低支持 macOS 和当前支持版本；按发布目标覆盖 arm64／x64，未覆盖的平台如实记录。
