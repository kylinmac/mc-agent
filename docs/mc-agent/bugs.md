## B-042 输入框上下文余量与左侧不一致

原因：输入框仍以最后一次模型请求用量计算容量，压缩后的左侧已使用运行时分类快照。两者混用时会显示 94% / 0%。

修复：共享按会话、模型配置、压缩和消息进度刷新的快照。加载或失败时不显示旧余量；切换会话后拒绝旧请求回写。模型请求的输入、输出和缓存统计保留原有语义。

验证：隔离 Electron 回归通过，覆盖旧请求 272.9k 与当前 14.1k / 256k、调整上限、压缩、跨会话延迟回包、失败及两入口请求去重。另通过 103 项相关回归、desktop 类型检查、lint（两条既有测试目录断链警告）、文档检查与 `git diff --check`。未使用安装版或真实模型服务。

## B-041 上下文统计跨压缩和模型配置混用

源码确认：左侧总量取最后一条历史消息的供应商用量，分类取当前运行时估算；压缩标记原先只参与会话分段，没有阻止总量继续读旧消息。分类刷新也未订阅压缩及模型配置变化；宿主发现已有运行时便直接返回，可能保留旧上限。

修正：

- 左侧总量、百分比和分类共用当前运行时快照。总剩余包含自动压缩预留；“剩余空间”和“距自动压缩”仍扣除预留，两者含义不变。
- 压缩、模型切换、上限设置变化时刷新；旧会话或旧配置的异步结果不得覆盖新视图。空闲本地运行时先同步配置，运行中的会话保留当前执行配置。
- 最近请求详情不再使用压缩边界以前或其他模型的用量；尚无有效的新请求用量时暂不显示请求详情。B-042 进一步让底部容量独立使用当前运行时快照；历史回复的累计用量不变。
- 获取失败显示现有未知状态，不回退到失效的历史统计。

验证：相关 Node 回归 37 项通过；桌面类型检查、lint、文档检查及 `git diff --check` 通过。桌面全量测试已尝试并中止：附件深层文件搜索界面用例缺少工作区 `electron.exe`，单独重跑同样失败，未完成全量与 Electron E2E。未调用真实模型，未操作用户正在使用的安装版；真实会话内容和安装版修复效果未验证。

## B-017 Codex 导入不全

本机只读核对：新版 Codex（命令行、IDE 插件、ChatGPT 桌面版里的 Codex）把对话列表放在 `~/.codex/state_<n>.sqlite` 的 `threads` 表，对话内容放在 `thread_history_<n>.sqlite` 的 `thread_items` 表。一次性的 `legacy_to_paginated` 迁移把旧的 rollout `.jsonl` 拷进历史库后删掉了原文件，`threads` 里 258 个用户对话只剩 12 个文件，部分已归档文件还改成了 `.jsonl.zst`。导入只扫 `sessions` 和 `archived_sessions` 下的 `.jsonl`，所以只看到十几个。

修复：[codex-history.ts](../../apps/desktop/electron/main/importers/codex-history.ts) 以只读方式打开版本号最高的两个库，列出 `source` 为 `cli`、`vscode` 且有对话内容的线程。`exec`（脚本调用）、guardian 审查、子智能体和附着线程不列出。仍有 rollout 文件的线程继续读文件：正在进行的线程，历史库里的内容可能不全。标题优先用 Codex 侧栏标题 `name`，没有时用第一条真实请求。转换保留用户消息、回复、命令、文件改动、MCP 调用和网页搜索；推理、压缩标记等内部记录不导入。文件扫描也不再列出 guardian 审查的 rollout。

验证：本机扫描从 15 个对话变为 259 个、96 个项目，249 个来自历史库的对话全部转换成功；mc-agent 项目与 Codex 侧栏一致（2 个对话加 1 个已归档）。ChatGPT 桌面版里没有对话的项目（如 codex-v）本机也没有记录，不会出现。

## B-016 对话里的目录链接点击和复制失败

源码确认：点击和右键复制都先走 `fs.resolveRef`，解析只接受普通文件（`chat-ref-resolve.ts` 的 `isRegularFile`），已存在的目录被当成“没有这个文件”；复制在解析失败后直接返回。

修复：精确路径（相对或绝对）指向项目或本会话 scratch 根内已存在的目录时，解析成功并标记 `directory: true`；包含规则与文件相同（软链接逃出根仍拒绝），后缀补全仍只匹配文件，附件库不匹配目录。点击目录总是在工作面板文件管理器中打开该目录（带行号也一样），文件管理器不可用时提示，不会当文件打开；复制完整／相对路径随解析成功即可用。这改变了上游 ADR 0262 补全“只匹配文件”的隐含约定，原测试“同名目录永不匹配”改为按目录解析。
