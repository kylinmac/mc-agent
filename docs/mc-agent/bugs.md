## B-015 Windows 标题栏右上角背景断开

源码确认：mc-agent 的标题栏使用 `--mc-chrome-bg`，窗口按钮仍沿用上游 `--ds-bg-primary` / `--ds-bg-dock-raised`。深色主题的 dock-raised 透明，露出下面的面板；浅色主题则显示另一块白色。

修复：在 [app-rail.css](../../apps/desktop/src/styles/app-rail.css) 统一主窗口按钮区域背景，覆盖面板打开时的上游规则。保留按钮尺寸、位置、悬停样式和不可拖动区域。Windows/Linux 共用的窗口按钮均生效，macOS 无此按钮组。

验证：使用完整样式表与最小 DOM 在 Chromium 中复现，修复前深浅主题均不同色；修复后 Windows/Linux × 深浅主题 × 面板关闭／打开／最大化共 12 组通过背景、等高、按钮命中和 no-drag 样式检查。这是 CSS 渲染验证，不等同原生 Electron 点击验证。[窗口按钮端到端测试](../../scripts/e2e-window-controls.mjs) 补充面板关闭时的标题栏同色检查。

未验证：完整 Electron 端到端和原生窗口操作。当前工作区没有依赖、桌面构建产物及 Rust host 二进制；未操作正在使用的桌面实例。

## B-001 `new_context` 在同一轮里压缩两次

日期：2026-10-22。模型：grok-4.7。会话几乎是空的，没有读文件、没有跑命令。

界面顺序：

1. 用户：新开个对话，啥也不干，你不用回复。
2. 已处理 2s，1 个工具。
3. 上下文已压缩，第 1 次，摘要约 153 tokens。
4. 已处理 2s，1 个工具。
5. 上下文已压缩，第 2 次，摘要约 199 tokens。
6. 模型又回复了「新对话已开，没有其他操作。」

源码路径（`packages/agent-runtime/src/runtime.ts`）：

- `new_context` 只把 `pendingModelCompaction` 设为 true，工具返回后循环不停止。
- 下一次模型请求前，`prepareNextTurn` 才真正压缩，然后用新窗口继续问模型。
- 进行中的回合会原样保留最新用户消息。模型又看到「新开个对话」，就再调一次。

摘要只有一百多 tokens，不是上下文满了，也不是加载了大量文件。两次工具行没有在界面里展开，工具名按这条路径推断，未从会话库核对。

## B-002 上下文分类不能第一时间出来

日期：2026-10-22。界面：左侧会话信息，「上下文」已展开。当时对话正在跑（处理中约 30s）。

截图里已经有「已用 10%」和「49.8k / 500.0k」，下面却是「在本会话发送一条消息后可查看分类」，再下面是「已压缩 0 次」。

源码路径：

- `apps/desktop/src/features/session-info/SessionInfo.tsx`：`breakdown` 初始是 `null`。回合进行中 `settledMessages` 为 `-1`，效果直接返回，不调用 `sessionContextBreakdown`。
- 同一个 `null` 一律显示 `sessionInfoNoBreakdown`。加载中、请求失败、回合进行中、真的没有分类，文案相同。
- `apps/desktop/electron/main/ipc/project-resources-ipc.ts` 注释写过：没有 runtime 时先加载，分类不必等下一条消息。渲染侧仍要等回合结束才请求。

期望：分类行始终画出来。数还没到，百分比显示 `?` 或 `0`，代币数同理。不要用「请先发一条消息」代替整块列表。

日期：2026-10-22。类型：品牌。建议优先级：P2。

复现：打开 `/Applications/mc-agent.app`（1.0.3），看 Dock。

实际：正在运行的那枚是黑色底、浅色 mi，下面有运行圆点。旁边另一枚是浅色底、深色 mi，带红色角标 4，不是当前打开的这枚。用户指出正式安装的图标打开后也是黑的。

核对（只读，未改安装包、未重启 Dock）：

- 安装包 `Contents/Resources/icon.icns` 与仓库 `apps/desktop/build/icon.icns` 字节相同。抽 `ic10`，背景是浅色 `(242,242,242)`，字形是深色。源文件 `icon.svg` 也是浅底。
- 黑色图对应 `apps/desktop/build/logo_dark.png`。
- 打包版不会调用 `app.dock.setIcon`。只有开发版会把 Dock 设成 `icon_1024.png`，那张也是浅色。

期望：正式安装运行时 Dock 用浅色 mi，和 `icon.svg` 一致。不要用黑色 logo。

未验证：为什么包内已经是浅色 icns，Dock 仍画出黑色。没重启 Dock，也没重装。不把图标缓存说成已证实原因。
