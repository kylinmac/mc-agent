# 云端发布（R16；P12；V52）

已确定（2026-10-23）：macOS arm64 与 Windows x64 都由 GitHub Actions 从同一个版本标签构建。macOS 沿用 ad-hoc 签名和应用内自更新；Windows 沿用 Setup 与 NSIS 静默更新。不得把旧版本包复制进新版本。

P12：Actions 中运行 `mc-agent Release`，填写版本号（不含 v）。标签须已存在且属于 main 历史。流程准备草稿、并行构建两端、验证产物与更新源，最后一次性公开；任何构建失败都不发布。已公开的版本不可覆盖。工作区版本号不随 fork 发版修改。

V52：验证非法版本、缺失文件、版本错配与 SHA-512 错配会失败；验证两端真实云端构建、macOS 签名与 helper、Windows 安装升级测试，以及最终草稿发布。首次运行结果另行记录，不把工作流存在当作验证通过。

发布操作：先让代码通过 PR 检查并合入 main，把该版本的更新说明写进 `mc-changelog-zh-CN.ts` 并合入（见[更新说明流程](release-notes.md)；prepare 会检查标签里有没有这一条，从 1.0.20 起），创建并推送 `v<版本>`，再运行 `gh workflow run mc-release.yml -f version=<版本>`。如已有草稿，可重跑；仅草稿允许替换同名产物。旧 `mc-windows.yml` 保留独立调试入口，统一发布流程复用其构建任务但关闭直接上传。

当前支持与既有正式包一致：macOS Apple Silicon、Windows x64。Intel Mac、Linux 不属于本次扩展。macOS 没有 Developer ID 公证，首次安装的系统提示和更新后权限行为保持现状。

## 自动检测（R16.1；P12；V53）

已确定（2026-10-23）：安装版启动并加载更新设置后约 15 秒自动检测，运行期间每小时检测。检测不阻塞开窗；下载和安装仍遵循现有更新偏好，不强制重启。开发版仍禁用更新检测。

V53：用虚拟时钟验证启动检测、连续两个 1 小时周期、重复启动调度不重复注册、一次失败不阻止下一次检测、关闭控制器后不再检测；沿用下载完成后继续检测新版本及重启更新的回归测试。

## CI 耗时调整（2026-11-03）

上一轮 CI `41603595784` 的 Rust 任务约 24 分 54 秒，其中测试约 24 分 18 秒；桌面分片约 3 分钟。Rust 按 core、config-sync、rpc 三组并行：core 排除后两组，config-sync 运行全部配置同步测试，rpc 排除已被配置同步组覆盖的名字。格式与 Clippy 只在 core 运行，测试不删减。缩短的是等待时间，额外 runner 和重复编译会增加资源消耗；实际提速待本轮 CI 验证。

发布 `41598681797` 的 Windows 打包约 6 分钟，安装升级验证约 41 秒；这些检查继续保留。版本说明改动已由 CI 路径规则排除全量重跑；更新说明、签名、安装升级、双平台产物和哈希校验不跳过。
