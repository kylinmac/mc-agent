## R21.1 压缩后可回查原文

### 工具与查询边界

- 新增只读工具（暂名 `ContextHistory`），运行时绑定当前会话；模型不能传任意会话或项目 ID。只查询选定检查点 `throughMessageId` 及之前的消息。该边界覆盖检查点保留的近期原文，不等同于“所有这些消息都已被摘要替换”。
- 首次查询固定检查点及其历史边界，后续游标沿用该范围。使用稳定消息 ID 和物理位置定位，不使用界面去重后的数组下标；连续压缩、fork、历史修订不得让旧游标静默改指另一段历史。无法维持范围时返回游标失效，要求重新查询。
- 参数支持有界分页、指定消息附近及可选关键词。响应包含消息 ID、原角色、时间、可读文本、扫描范围、下一游标、是否完成扫描及截断标记。无压缩、锚点缺失或越界时明确返回状态，不偷偷改查最新尾部。
- 关键词第一版可过滤有限页，但限制扫描页数、字节量和耗时，并支持取消。未扫描完整范围时只说“已扫描范围未找到”，不能声称历史中不存在。现有搜索接口先核对会话和边界过滤能力，不直接开放跨会话搜索。

### 读取与输出契约

优先复用 `session.get` 的底层窗口读取能力，但不承诺完全不改 Rust。它目前面向 Renderer，不能直接把整个 `SessionDetail` 当作工具结果：

| 源码确认的差异 | 本工具要求 |
| --- | --- |
| #57 的 `messageParents` 和已有 `navigationParent` 是页外展示补充 | 排除这些字段，不注入模型、不参与游标或计数；同时评估复用接口是否带来不必要的父任务扫描 |
| `UiMessage` 含 thinking，返回还含会话元数据与检查点 | 使用字段白名单；仅投影允许的正文、工具名和必要参数／结果文本，不返回隐藏推理、内部元数据和附件二进制 |
| `messageAround` 对命中用户／助手正文可能绕过显示截断 | 独立限制最终工具输出总 tokens / 字节，不能只依赖 `contentLimit` |
| 现有分页不会自动按本工具的压缩边界裁定范围 | 所有读取模式均验证检查点上界；禁止 around 查询带出边界后的相邻消息 |

SQLite 仍只由 host-core 读写，不导出一份供模型任意访问的全量日志。若复用现有 RPC 无法同时保证边界、数据最小化和成本，则增加最小的有界只读宿主接口；生产方、消费方及类型同时更新。

两条宿主侧约束（源码确认，实施前定稿）：

- **全局锁与并发一致性**：`session.get` 先取 host-core 全局状态锁（`rpc/mod.rs` 的 `state.lock().await`），持锁期间读取 transcript 文件；回查多页扫描时，其他需要同一状态锁的请求阶段（含 `tools.execute` 的部分阶段）会等待。新接口应在锁外读取文件，锁内只取必要状态。释放锁后会话可能被删除、历史可能被重写（如 `session.replaceMessages`），不能拿旧布局偏移直接读新文件：读取时核对文件身份、检查点边界和布局有效性，变化时有限重试或返回游标失效。同步文件读取放到阻塞线程，不占用异步执行线程。小页数不保证低耗时：布局重建（`with_layout_recovery` 会整文件重扫）和页外父任务查找仍可能扫描长历史，需一并限时并实测。不带 `messageLimit` 的 `session.get` 会读全量 transcript，工具每次调用都必须带上限。
- **会话归属**：一个 sidecar 内有多个会话 runtime（`packages/agent-runtime/src/sidecar.ts` 的 `runtimes` 按会话 ID 存放），白名单位于 `packages/host-runtime/src/agent-sidecar.ts` 的 `HOST_PROXY_ALLOWED`，不能按“sidecar 所属的单个会话”校验。新回查接口绑定可信的运行会话上下文，校验目标会话与调用归属一致，不能只信任请求里的 `sessionId`。可信关联如何传递先定契约；不顺手把所有 `session.get` 改成单会话限制。

历史结果作为数据进入普通工具预算，不作为新授权或新指令。回查到旧批准不代表当前操作获得批准；最新用户修正和现行权限仍优先。

### 声明与验证

工具实际可调用时才在摘要接续提示里说明入口。检查主代理、子代理、远程及非 Agent 模式的实际工具能力；不通过修改全局常量给所有场景都宣告支持。懒加载下保证声明可发现，或将其作为已具备能力的固定只读工具，不出现“提示可用、调用不存在”。

验证覆盖：当前会话绑定（含宿主侧拒绝与调用归属不一致的会话 ID）、扫描期间其他会话请求不被长时间阻塞、锁外读取时会话删除／历史重写／布局重建、无压缩、边界外 around、完整大正文、隐藏推理排除、页外父任务排除、扫描未完成与真无匹配、连续压缩及游标失效、取消、工具声明与提示一致。隔离 Electron 走一次压缩后回查；大历史性能另测，不把已有 UI 分页回归当作模型回查验证。

## R21.2 小预算的文件片段恢复

### 候选与收益

先用 01 回查历史或正常 Read 按需读取，再评估自动恢复的收益。自动恢复是可选补充，不能成为每次压缩都重读文件的固定步骤。

- 在 `pi-runtime-compaction-plan.ts` 的文件操作收集基础上，关联成功的工具结果及最后操作位置；不把失败或被拒绝的调用参数当作已读文件。
- 优先最近成功读取且仍用于当前工作的文本片段，保留路径、读取范围及关联操作。第一版用可解释的候选规则，不额外调用模型判断相关性；不能确认范围或关联时只保留路径供按需读取。
- 近期原文已保留相同范围且没有后续已知修改时跳过。只看到同一路径不代表已经保留完整内容；Read 后发生 Edit / Write 的情况单独验证。
- 重新读取当前片段，注明读取时间、行范围和截断情况；明确这是压缩期间读到的快照，可能与历史记录不同，也不保证下一步执行时文件未变。

建议初始上限：最多 5 个文件，单文件不超过 5K tokens，合计不超过 8K tokens；均为上限，不是必须填满的目标。取消原提案在 5 × 5K 限制下不起作用的 50K 总上限。

有效附回预算取总上限与实际可用空间的较小值。计量包括 system、工具声明、摘要、保留原文、reasoning replay、附件包壳；复用既有安全预算，避免重复扣除已预留的输出空间。安装后必须低于自动触发线并留出增长余量，且比压缩前实际缩小。不满足时依次减少附件直至零个，不能删除关键摘要或必要原文来容纳附件。余量初值在实现前明确并用小窗口回归验证；没有净收益时沿用原有无进展处理，不把相同结果循环安装为成功。

### 无交互权限与时限

当前 `tools.execute` 在自动判断不能放行时会创建审批请求并等待，所以“调用普通 Read，再把需审批的错误忽略”不能实现无弹窗。

- 在宿主执行边界支持“仅已有权限允许时执行，否则返回 skipped”的内部调用模式。只缩小权限，不允许模型参数选择绕过审批；普通 Read 行为不变。
- 共用原权限判断、会话／委派工作区解析、路径和符号链接校验，以及实际远程路由；执行时仍复核。无需审批不等于忽略显式拒绝。
- 二进制、不支持的读取范围、外部路径、已删除文件和远程断连直接跳过。记录结构化跳过原因，不记录敏感正文，不伪装成读取成功。
- 整个恢复阶段有独立短时限和有限并发，Stop 可取消底层读取；时限耗尽保留已完成的合法片段。实现前明确默认时限并测远程慢读，不能沿用 180 秒静默预算逐个等文件。

### 检查点与重建

修订方案统一为：附回快照与摘要分字段保存在同一检查点，持久化成功后再安装活动上下文。重启和重建只用已保存快照，不重新读取；若持久化失败，不能报告整体压缩完成。

**沿用既有顺序**（源码确认）：`runtime.ts` 的 `persistCheckpoint` 先等待 `session.appendCompaction` 成功，再设置 `activeCompaction` 并替换模型消息，失败直接返回；宿主写入提交后才回复 RPC。附回快照纳入同一检查点即可，不重做摘要持久化；补附件写入失败（含超大、序列化失败）时不安装、不报告成功的回归。

在现有 `session-context.ts` 重建规则中接入专门的恢复上下文消息，顺序为既有 system 恢复、摘要、文件恢复上下文、既有 reasoning replay（仅需要它的模型存在）与保留尾部，再接边界后的新消息。验证各 provider 的合法消息结构，保持调用／结果配对，不伪造用户要求或工具调用。摘要与文件恢复会成为相邻的两条 user 消息；需要 reasoning replay 的模型其后接 assistant 消息。逐个适配器确认相邻 user 消息被接受；需要合并时仅在发送模型前合并，持久化仍分字段，不把文件内容混进摘要正文。不在聊天里新增一次假的工具执行，但可在压缩诊断里展示恢复数量和跳过原因。

再次压缩不把附件当作新用户请求，不反复追加旧快照；旧版无附件字段的检查点仍可读取。明确字段版本、大小限制和 fork 复制语义；若需要改变数据库 schema，补迁移及升级测试，不能假设空库。权限或存储架构边界变化按仓库要求补 ADR。

验证覆盖：成功结果选取、失败调用排除、同文件不同片段、读取后修改、空预算、小窗口、净收益、路径越界／符号链接、无需审批且不产生审批事件、远程慢读与取消、写入失败、重启不重读、多次压缩不累计、旧检查点及 fork 兼容。

## R21.3 摘要请求复用提示词缓存

### 先测量，沿用推理与会话身份

复用现有用量与诊断，按摘要阶段和尝试记录输入、cacheRead / cacheWrite、输出、耗时及退回原因；用量不可用要标未知，不记为零。不记录历史正文、密钥或隐藏推理。比较整个压缩过程的总耗时与总用量，不能只看某次成功请求。

源码确认：`compaction-request.ts` 已恢复会话关联和 Responses / Codex 的 `prompt_cache_key`，即使专用摘要指定 `cacheRetention: "none"`。新方案复用该入口，重点调整内容前缀，不重复建立会话标识机制。

默认保持 R20 的推理规则和 #59 的篇幅预算，不为可能命中缓存重新启用高努力程度。不同 provider 的推理变化是否影响缓存，属于待测事实；无收益可维持专用摘要请求，不要求用户预先在速度与缓存间选 A/B。

### 请求与退回

- 仅在完整输入加摘要指令和输出余量放得下时试验对话形摘要请求：复用普通请求的 system、工具声明与消息转换，末尾追加摘要指令。维持历史数据边界和“只总结、不继续任务”的要求。
- 第一阶段选择一个已验证适配器；Anthropic Messages、OpenAI Responses / Codex 分别核对请求结构，不承诺一个分支同时覆盖所有服务商。分块和超窗缩减继续使用现有路径。
- 带工具声明不代表允许执行工具。摘要请求不进入 Agent 工具循环；若模型仍返回工具调用，不执行它。
- 假服务校验预期可共享的稳定前缀字段及消息序列；动态请求 ID、时间戳等单独断言，不能要求整个请求逐字节一致。提示词相似或同一个 cache key 都不等于实测命中。

| 结果 | 处理 |
| --- | --- |
| 成功且完整的摘要 | 按现有规则计量、持久化并安装 |
| 工具调用、空文本或明确的请求格式不兼容 | 可退回专用摘要一次，记录原因和已发生用量 |
| 输出被截断 | 仍不作为成功摘要；沿用 #59 短重试，并与退回共用预算 |
| 用户停止、会话销毁 | 立即取消，不发起退回请求 |
| 认证或配额错误 | 不通过换摘要格式重复请求；按既有错误分类结束 |
| 瞬时网络错误、限流或静默超时 | 沿用已有分类、退避与取消规则，不另起无限重试链 |

缓存尝试、格式退回、截断重试和瞬时重试由同一份尝试预算约束，不为退回重置计数；实现前写清总上限及不同摘要阶段的计数。已取消请求必须结束后再重试，保持 #55 的静默保护和 #59 的界面计数语义。退回成功只代表最终成功，前一次失败、耗时和用量仍要记录，不能写成“不计为失败”。

验证覆盖：稳定前缀、已有 cache key 不被覆盖、推理省略／低等级、工具绝不执行、所有退回分类、预算耗尽、停止期间不再请求、累计用量、安装一次且失败不落盘为成功摘要。真实服务商的缓存命中率、费用和速度需用户同意后测量。

## R21.1 实现记录（2026-10-30，开发分支）

源码确认，离线验证通过；未合入、未发布，未用真实模型测试。

| 层 | 实现 |
| --- | --- |
| host-core | `transcripts/history.rs` 只读检查点及其 `throughMessageId` 之前的消息：倒序读取检查点行，逐页读取消息行，不读全量 transcript。位置只在同一布局快照内使用，偏移失效时由既有 `with_layout_recovery` 重建一次；游标用稳定消息 ID。`rpc/mc_session_history_rpc.rs` 的 `session.historyRead` 只在状态锁内确认会话存在并复制数据目录，读取放到 `spawn_blocking`；不返回 thinking、页外父记录、子代理行（`parentToolCallId`）、附件正文 |
