# mc-agent 验收与开发计划

状态：文档阶段，所有运行验证均未执行。采用 Fork 后先验证继承能力，再验证项目管理增量；不再从自建内核和协议开始。

## 1 基础能力回归

| 编号 | 需求 | 场景 | 通过标准 |
|---|---|---|---|
| V1 | R1 | 模型 API、OAuth 登录／刷新／退出、错误凭据 | 所列组合按实际结果标通过或受限；凭据不泄漏 |
| V2 | R2 | 流式与连续两轮对话 | 内容无重复，上下文和终态正确 |
| V3 | R3 | 读取、写入、命令及相关工具 | 保持上游行为，实际结果可检查 |
| V4 | R4 | 各权限模式、Plan／Goal 允许与拒绝 | 不能绕过授权，不串会话 |
| V5 | R5 | 立即停止与完成当前批次后停止 | 行为符合既有语义，已发生副作用可见 |
| V6 | R6 | 会话历史、搜索、分支、重启、导入副本 | 数据保留，异常任务不标成功 |
| V7 | R7 | 模型断线、工具失败、内核退出 | UI 可用，错误清楚，不重复未知写入 |
| V8 | R8 | 插话与消息排队 | 消费一次、时机符合上游、归属正确 |
| V9 | R3 R4 | 两个项目、worktree、越界与符号链接 | 执行范围来自会话绑定，不来自当前侧栏 |
| V10 | R6 | 升级、损坏记录、磁盘满 | 保留可恢复数据，失败不伪装保存成功 |

另对受改动影响的插件、MCP、Skills、多 Agent、定时等执行上游对应回归。不要把“存在测试脚本”标记为测试通过。

## 2 新增项目管理验收

| 编号 | 需求 | 场景 | 通过标准 |
|---|---|---|---|
| V11 | R9 | 两项目分别有待办、阻塞和待验收 | 概览计数准确，不混入另一项目 |
| V12 | R10 | 登记文件／URL、分类、打开、解除关联 | 文件位置不变；解除关联不删除原件 |
| V13 | R11 | 确认文件后由外部编辑器修改 | 检出变化，不把新内容冒充已确认版本 |
| V14 | R12 | 同一任务两次执行并重启 | 任务 ID、验收条件和执行历史持续存在 |
| V15 | R13 | 选资料启动、缺失资料、超限资料 | 上下文可核对；失败阻止启动；无静默截断 |
| V16 | R13 R15 | 连点启动、跨项目伪造 ID、启动中崩溃 | 不重复执行，不越权关联，恢复时先核实 |
| V17 | R14 | Agent 说完成，用户检查后通过或退回 | 初始只到待验收；用户结论与证据留存 |
| V18 | R15 | 文件移动／删除、删除会话、归档项目 | 可修复或显示缺失，不丢历史验收、不误删原件 |
| V19 | R11 R13 | 主目录与 worktree 同名文件不同内容 | 明确本次依据的实际位置和哈希 |
| V20 | R12 R14 | 任务停止、工具失败或模型中断 | 任务不变成完成，保留已经产生的结果 |

|---|---|---|
| S1 整理资料 | 一个文档较分散的真实项目 | 从概览找到需求、架构、原型及当前状态 |
