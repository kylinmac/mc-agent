# mc-agent 需求文档

版本：草案 0.3（2026-10-14）。产品定位、macOS 首发、Fork、开源，以及新增需求 R1–R10 的范围与阶段已确认；接口、表结构等技术细节未冻结。当前阶段只完善文档。

## 1 产品定位

**一句话**：为工作室、OPC 和多项目开发用户提供以项目管理为核心的桌面 Agent，把项目文档、资源、任务与开发结果组织在一起，让 Agent 基于明确的项目资料开展开发。

| 项目 | 已填写的定位 |
|---|---|
| 目标用户 | 工作室、OPC、多项目开发用户 |
| 主要痛点 | 现有 Agent 对项目的管理不够友好，文档和资源维护较差 |
| 首版成功标准 | 做好项目管理，并利用项目管理更好地开发项目；下文给出可验收的建议 |
| 首发平台 | macOS |
| 模型服务及凭据来源 | 目标是支持 Pi 提供的 API 与登录方式；继承上游，逐项建立兼容验证清单 |
| 产品差异 | 项目管理 |
| 开发底座 | Fork PI-Desktop，接受其开源许可方向 |

工作室是目标用户群，不自动意味着首版需要多人云协作。建议首版先解决单机管理多个项目；协作方式列为待确认。

## 2 产品边界

基础 Agent 直接继承，不重新开发一套。新增价值是：
**项目资料 → 有验收条件的开发任务 → 执行会话 → 产物与验证 → 用户确认完成。**

保留上游已有插件、多 Agent、定时等能力；“首版不扩展”不等于删除。上游声称支持的能力，需经过 macOS 回归才能标为本产品已验证。

详细依据见[功能与缺口分析](pi-desktop-analysis.md)。

## 3 三个核心场景

以下是由定位推导的场景，待你用真实项目确认。

| 场景 | 输入与前置条件 | 用户结果 | 完成判据 |
|---|---|---|---|
| S1 接手一个已有项目 | 本地项目及分散的需求、架构、原型、参考资源 | 一个项目入口可找到资料、状态和相关会话 | 资料能打开，分类明确，已确认版本与草稿不混淆 |
| S2 按文档开发一项功能 | 选定需求资料、目标、验收条件 | 建立任务并启动 Agent，结果可追溯到依据 | 任务能跳转到会话、产物、验证记录；用户确认后完成 |
| S3 多项目切换后继续工作 | 两个项目和一个未完成任务，期间文档有变化 | 继续正确项目，知道上次做到哪、依据是否变化 | 无跨项目串用；变化或缺失明确提示；重启后关联仍在 |

## 4 继承的基础 Agent 能力

B 编号是继承能力，只做回归验收，不是新建待办。

| 编号 | 继承能力 | 验收重点 |
|---|---|---|
| B1 | 模型、API 和账号登录 | 覆盖所选版本支持范围；登录、刷新、退出、错误均可辨识 |
| B2 | 连续对话与流式输出 | 上下文正确、内容不重复、终态明确 |
| B3 | 文件、命令及其他既有工具 | 保持工具范围和权限，能查看结果 |
| B4 | 审批和模式 | 保留已有权限、Plan／Goal 的授权边界 |
| B5 | 停止 | 区分立即停止与完成当前批次后停止，不承诺自动撤销 |
| B6 | 会话历史、搜索、分支和项目组织 | 不破坏原有数据，重启后可查看 |
| B7 | 错误、恢复及重试 | 不把失败显示为成功，不重复未知副作用 |
| B8 | 运行中插话和消息排队 | 沿用上游时机与归属，不降级为新开发 P1 |

其他已有能力纳入功能清单和变更影响回归；本轮没有证明所有上游能力均可靠可用。

|---|---|---|
| 首版 | R1 项目结构、R10 工作区说明、R2 项目概览、R3 资料列表、R4 资料确认 | 项目和资料部分；R10 于 2026-10-15 追加，排在 R1 之后 |
| 首版后续 | R5 模板迁移 | P1，跟在 R1 之后 |
| 第二阶段 | R6 项目任务、R7 从任务启动、R8 验收、R9 失效修复 | 任务闭环；资料文件的移动／删除提示在首版由 R3、R4 覆盖 |

全部 2026-10-14 经用户确认。当前没有待评审的 X 提案。

### 5.1 项目结构（R1）

R1 是其他需求的前提：项目由哪些目录组成、资料放在哪、会话从哪里起步，都由它决定。决定记录见 [MC-ADR-0003](adr/mc-0003-equal-workspaces-and-project-home.md)。

| 编号 | 内容 | 规则 | 通过标准 |
|---|---|---|---|
| R1.1 | 工作区平等 | 项目可有一个或多个工作区，界面不分主次；项目身份用项目 ID；目录可标为“外部资料”，只改标识与整理方式，权限与工作区相同 | 前后端分离项目的各仓库地位相同；改动任一工作区不改变项目身份 |
| R1.2 | 项目资料目录 | 管理项目有一个，默认 `~/Documents/mc-agent/projects/<项目名>/`，在所有工作区之外；简单项目没有 | 新建管理项目时创建；Agent 读写资料目录不弹外部路径授权；删除项目默认不删目录 |
| R1.3 | 改名同步 | 项目改名时资料目录跟着改名 | 运行中的会话阻止改名；重名自动加后缀；非法字符替换；失败回滚目录名；改名后会话、资料、任务都能找到 |
| R1.4 | 模板 | 内置 `software`（requirements / architecture / prototype / reference）和 `blank`；支持在应用里编辑和新增模板（项目工作台“管理模板”：增删分类、改说明、复制新建、删除到 `.trash`；起始文件在访达中编辑）；只在创建时复制一次 | 模板可带子目录和起始文件；改模板不影响已有项目；目录名用英文 |
| R1.5 | 起始目录 | 会话可从资料目录或任一工作区起步；记住每个项目上次的选择 | 相对路径、Shell cwd、AGENTS.md 都以起始目录为准；给模型的说明列出起始目录和其他目录 |
| R1.6 | 统筹与派工 | 主会话在资料目录统筹；Worker 会话可指定同项目的目标工作区启动 | Worker 在目标工作区加载该处 AGENTS.md；不能指定项目外的目录 |
| R1.7 | 新建类型 | 新建时三选一：对话（不属于项目）、简单项目（只有文件夹，上游原样，默认）、管理项目（资料目录与模板）；不另存类型，有资料目录即管理项目 | 简单项目不显示资料、任务、模板；可手动“转为管理项目”，也可“解除资料目录”退回（文件保留）；再次转换时接回原资料目录 |

补充规则：
- 每个会话只自动加载起始目录的 AGENTS.md；其他工作区的只列出路径，用到时再读。
- 上游 `primaryPath` 字段保留，只作内部兼容，不在界面上表示主次。
- 远程项目首版不纳入 R1。
- 已有项目不再自动建资料目录（2026-10-19 改），保持为简单项目，需要时在工作台手动“转为管理项目”。

### 5.1.1 工作区说明（R10）

| 编号 | 内容 | 规则 | 通过标准 |
|---|---|---|---|
| R10 | 工作区说明 | 每个工作区一句说明，存放在资料目录根下的 `workspaces.md`，每个工作区一节，标题为工作区文件夹名（同名时用路径区分）；界面可编辑，也可在任何编辑器里改 | 项目页显示说明；启动会话时，给模型的工作区列表带上各工作区说明；界面编辑只改对应一节，其他内容原样保留；文件缺失或某节缺失时视为没有说明，不报错 |

补充规则：
- 详细规则仍写在各工作区自己的 `AGENTS.md`；`workspaces.md` 只说明“哪个工作区做什么”，供统筹和派工使用。
- 资料目录根下的 `workspaces.md` 与 `AGENTS.md` 是保留文件：不算分类，不出现在资料列表（R3）。
- `software` 模板预置这两个文件的样板，`blank` 不预置。
- 每次使用时重新读取文件，外部修改即时生效。

### 5.2 项目与资料（R2–R4）

| 编号 | 新增能力 | 最小范围 | 通过标准 |
|---|---|---|---|
| R2 | 项目概览 | 目标、资料状态、任务进度、待验收入口；点开项目默认进入概览，会话列表作为其中一个标签页 | 从一个入口定位当前任务及阻塞，统计来自实际状态；第二阶段前任务相关区块为空态 |
| R3 | 项目资料列表 | 资料目录内的文件自动列出，一级子目录即分类（由模板决定）；工作区内的文件和 URL 登记到对应分类的 `INDEX.md`（Markdown 链接清单），不复制原文件 | 不搬动原文件；可打开、编辑登记信息和解除关联；忽略 `.git`、`.DS_Store` 等 |
| R4 | 资料确认与变更提示 | 草稿、已确认、已废弃；确认时记录本地文件内容哈希 | 文件变化后提示“确认版本已变化”，不继续显示为当前已确认 |

不确认的资料照样能用，只标“草稿”；确认的意义在于之后文件变了能提示。

### 5.3 模板迁移（R5，P1）

| 编号 | 内容 | 规则 | 通过标准 |
|---|---|---|---|
| R5 | AI 整理资料 | 选一个模板和模型，在资料目录起一个 Agent 模式会话直接整理（来源文件 → 分类，登记到 INDEX.md、移动或起草）；动手前在对话里列出将做的事，用户在对话中查看或停止（2026-10-15 改为直接执行）。也用于给已有项目换模板；默认选项目当前模板；按各目录类型与说明处理；某分类没有对应文档时，AI 根据读到的内容起草新文档（标注“AI 草稿”与来源），进资料列表为草稿 | 工作区文档只登记不复制，原文件不变；移动只限资料目录内；执行结果和计划可对照 |

复用上游 Plan 审批和会话选模型，不另做一套执行器。排在 R1 之后。

### 5.3.1 界面外壳（R11）

参照 ChatGPT 桌面版的布局；决定与影响见 [MC-ADR-0004](adr/mc-0004-app-rail-and-title-tabs.md)。

| 编号 | 新增能力 | 最小范围 | 通过标准 |
|---|---|---|---|
| R11.1 | 侧边栏按项目合并 | 同一项目各目录的会话归在一个项目下，会话前标起始目录（资料、工作区名）；已不存在的目录在没有会话时隐藏 | 不再出现同名重复项目；拖动会话到同一项目不算移动 |
| R11.2 | 左侧竖栏 | 窗口最左一列，侧边栏收起时仍在；上段为内置入口（扩展、定时任务），分隔线下为插件预留区，设置单独在底部；提示显示在图标右侧 | 收起侧边栏后标题栏完整一行，不被竖栏切断 |
| R11.3 | 顶部标签栏 | 所有页面顶部为同一条深色标签栏；对话和扩展、定时任务、设置都以标签打开；关闭当前标签切到相邻标签；“+”新建任务；通知在右端 | 标签顺序按打开先后，不随切换跳动；被删除的会话标签自动去掉 |
| R11.4 | 设置以标签打开 | 设置页渲染在主区域；设置自己的导航占据侧边栏会话列表的位置；竖栏顶部“会话”图标切回会话列表 | 设置导航与搜索可用；内容区不显示页面大标题；无“返回应用”按钮 |
| R11.6 | 会话信息栏 | 对话区左侧：环境（项目、起始目录、分支、模型）、上下文用量与按类别拆分（消息、系统提示、内置工具、MCP 工具、技能、AGENTS.md、项目记忆、自动压缩预留、剩余空间）、改动、派出的 Worker、MCP 连接器 | 左上角一个按钮开合（没有单独的标题栏和关闭按钮），点别处不关闭；主区域够宽时停靠、对话与输入框随之收窄，窄时以浮层展开在按钮下方；分区可折叠、拖动标题排序、在“…”菜单里选显示哪些分区并恢复默认；右边缘拖动调宽（双击复原）；工具与技能行可展开名称；“压缩会话”按钮；布局记在本机；按类别数字为运行时估算 |
| R11.7 | 工作面板终端与工具 | 标题右侧工具图标：终端、审阅、浏览器、文件；终端在当前会话起始目录启动，可开多个；浏览器可开多个标签；面板标题并入深色标题栏（[MC-ADR-0005](adr/mc-0005-work-panel-terminal-and-tools.md)） | 终端 `pwd` 为起始目录；关闭标签结束 shell；项目外目录拒绝启动 |
| R11.5 | 品牌标识 | 应用图标、菜单栏图标、应用内 logo 改为 mi；外壳名称为 mc-agent | 任务栏能与已安装的 PI-Desktop 区分 |

### 5.4 任务闭环（R6–R9，第二阶段）

关联关系和持久化规则见[协议与数据](protocol-data.md)。

| 编号 | 新增能力 | 最小范围 | 通过标准 |
|---|---|---|---|
| R6 | 项目开发任务 | 稳定 ID、标题、目标、验收条件（必填，可由 AI 起草后用户修改）、引用资料、关联会话 | 跨会话保持同一任务；不以会话标题充当任务身份 |
| R7 | 从任务启动 Agent | 预览资料清单，明确选择后调用已有会话启动路径 | 记录本次依据；缺失必需资料时阻止启动，不静默略过 |
| R8 | 结果与验收 | 关联产物、验证说明、用户验收结果 | Agent 完成后只进入待验收；用户确认后才变成已完成 |
| R9 | 失效修复与持久化 | 文件移动／删除、并发修改、关联重开、项目身份变化 | 可修复链接；旧记录可追溯；不误删原文件或串项目 |

补充规则：
- 首版资料正文直接使用原文件；支持 Markdown／纯文本作为任务上下文。其他文件可登记和打开，是否读取由既有能力和权限决定，不承诺 PDF／Office 自动解析。
- URL 首版作为参考链接，不自动抓取网页或承诺远端版本锁定。需要它作为确定依据时，先保存本地快照。
- 任务可关联多次执行；建议每次通过 Desktop 托管会话执行。一次会话完整归属一个项目任务，避免首版复杂映射。
- Agent 可提出任务草案和结果；用户决定任务范围和最终验收。暂不新增自主批量调度器。

## 6 任务状态与异常

建议状态：待办 → 进行中 → 待验收 → 已完成；可转为阻塞或取消，验收不通过回到待办。停止／失败不等于完成，保留已有产物并进入阻塞。

用户可在普通聊天中继续自由使用 Agent；资料确认门槛只适用于“从项目任务启动”的管理流程，不额外限制普通对话。

关联资料变化后标出受影响的任务。运行中的任务继续记录原依据，不自动切换新版本；下次执行重新核对。已完成任务保留历史验收，不因新版本出现自动变成未完成。

## 7 首版不新增的范围

多人云同步、组织权限、复杂排期和依赖图、跨项目自动调度、全量知识库检索、完整在线文档编辑器、“把项目另存为模板”。记忆、会话待办及现有插件等直接复用；多目录项目按 R1 调整为不分主次。

## 8 质量和验收目标

- 数据：资料文件仍由用户持有；解除关联不删除原文件；外部修改不被静默覆盖。
- 权限：项目资料不升级成系统指令；跨根目录和 worktree 访问遵守既有授权。
- 可追溯：每次任务执行能查到资料清单、确认版本、会话、产物与验收结果。
- 体验：键盘可操作，状态有文字说明，找不到文件时有修复入口。
- 模型：版本、服务和登录范围明确列出，通过与未测分开标注。
- 性能：先用真实样例测量；首版资料数量、单份大小和总上下文预算在开发前确定，不能无限注入。
