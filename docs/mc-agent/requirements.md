# mc-agent 需求文档

2026-10-23 澄清：[R11.12 Windows 左侧标题栏](windows-titlebar.md)，对应 P11、V51；Windows 通知移到左侧，保留竖栏小房子入口，去掉顶部 mc-agent 品牌按钮。

版本：草案 0.4（2026-10-22）。产品定位、macOS 首发、Fork、开源，以及新增需求 R1–R14 的范围已确认。已进入开发阶段：需求写在这里，代码是否合入、验收是否通过分别看[验收与开发计划](validation-plan.md)第 2.1 节，不能因为有编号或有代码就认定已发布或已验收。（2026-10-14 的“先只完善文档”为历史阶段说明。）

## 1 产品定位

**一句话**：为工作室、OPC 和多项目开发用户提供以项目管理为核心的桌面 Agent，把项目文档、资源、任务与开发结果组织在一起，让 Agent 基于明确的项目资料开展开发。

| 项目 | 已填写的定位 |
|---|---|
| 目标用户 | 工作室、OPC、多项目开发用户 |
| 主要痛点 | 现有 Agent 对项目的管理不够友好，文档和资源维护较差 |
| 首版成功标准 | 做好项目管理，并利用项目管理更好地开发项目；下文给出可验收的建议 |
| 首发平台 | macOS |
| 模型服务及凭据来源 | 目标是支持 Pi 提供的 API 与登录方式；继承上游，逐项建立兼容验证清单 |
| 产品差异 | 项目管理 |
| 开发底座 | Fork PI-Desktop，接受其开源许可方向 |

工作室是目标用户群，不自动意味着首版需要多人云协作。建议首版先解决单机管理多个项目；协作方式列为待确认。

## 2 产品边界

基础 Agent 直接继承，不重新开发一套。新增价值是：
**项目资料 → 有验收条件的开发任务 → 执行会话 → 产物与验证 → 用户确认完成。**

保留上游已有插件、多 Agent、定时等能力；“首版不扩展”不等于删除。上游声称支持的能力，需经过 macOS 回归才能标为本产品已验证。

详细依据见[功能与缺口分析](pi-desktop-analysis.md)。

## 3 三个核心场景

以下是由定位推导的场景，待你用真实项目确认。

| 场景 | 输入与前置条件 | 用户结果 | 完成判据 |
|---|---|---|---|
| S1 接手一个已有项目 | 本地项目及分散的需求、架构、原型、参考资源 | 一个项目入口可找到资料、状态和相关会话 | 资料能打开，分类明确，已确认版本与草稿不混淆 |
| S2 按文档开发一项功能 | 选定需求资料、目标、验收条件 | 建立任务并启动 Agent，结果可追溯到依据 | 任务能跳转到会话、产物、验证记录；用户确认后完成 |
| S3 多项目切换后继续工作 | 两个项目和一个未完成任务，期间文档有变化 | 继续正确项目，知道上次做到哪、依据是否变化 | 无跨项目串用；变化或缺失明确提示；重启后关联仍在 |

## 4 继承的基础 Agent 能力

B 编号是继承能力，只做回归验收，不是新建待办。

| 编号 | 继承能力 | 验收重点 |
|---|---|---|
| B1 | 模型、API 和账号登录 | 覆盖所选版本支持范围；登录、刷新、退出、错误均可辨识 |
| B2 | 连续对话与流式输出 | 上下文正确、内容不重复、终态明确 |
| B3 | 文件、命令及其他既有工具 | 保持工具范围和权限，能查看结果 |
| B4 | 审批和模式 | 保留已有权限、Plan／Goal 的授权边界 |
| B5 | 停止 | 区分立即停止与完成当前批次后停止，不承诺自动撤销 |

其他已有能力纳入功能清单和变更影响回归；本轮没有证明所有上游能力均可靠可用。

### 5.1 项目结构（R1）

R1 是其他需求的前提：项目由哪些目录组成、资料放在哪、会话从哪里起步，都由它决定。决定记录见 [MC-ADR-0003](adr/mc-0003-equal-workspaces-and-project-home.md)。

| 编号 | 内容 | 规则 | 通过标准 |
|---|---|---|---|
| R1.1 | 工作区平等 | 项目可有一个或多个工作区，界面不分主次；项目身份用项目 ID；目录可标为“外部资料”，只改标识与整理方式，权限与工作区相同 | 前后端分离项目的各仓库地位相同；改动任一工作区不改变项目身份 |
| R1.2 | 项目资料目录 | 模板项目有一个，默认 `~/Documents/mc-agent/projects/<项目名>/`，在所有工作区之外；简单项目没有 | 新建模板项目时创建；Agent 读写资料目录不弹外部路径授权；删除项目默认不删目录 |
| R1.3 | 改名同步 | 项目改名时资料目录跟着改名 | 运行中的会话阻止改名；重名自动加后缀；非法字符替换；失败回滚目录名；改名后会话、资料、任务都能找到 |
| R1.4 | 模板 | 内置 `software`（requirements / architecture / prototype / reference）和 `blank`；支持在应用里编辑和新增模板（设置 → 项目模板：一个模板一张卡片，文件夹按树形多层管理、每层有说明，复制新建、删除到 `.trash`；新建对话框和项目工作台有入口跳转；起始文件在访达中编辑）；只在创建时复制一次 | 模板可带子目录和起始文件；改模板不影响已有项目；目录名用英文 |
| R1.5 | 起始目录 | 会话可从资料目录或任一工作区起步；记住每个项目上次的选择 | 相对路径、Shell cwd、AGENTS.md 都以起始目录为准；给模型的说明列出起始目录和其他目录 |
| R1.6 | 统筹与派工 | 主会话在资料目录统筹；Worker 会话可指定同项目的目标工作区启动 | Worker 在目标工作区加载该处 AGENTS.md；不能指定项目外的目录 |
| R1.7 | 新建类型 | 新建时三选一：对话（不属于项目）、简单项目（只有文件夹，上游原样，默认）、模板项目（资料目录与模板）；不另存类型，有资料目录即模板项目 | 简单项目不显示资料、任务、模板；可手动“转为模板项目”，也可“解除资料目录”退回（文件保留）；再次转换时接回原资料目录 |
| R1.8 | 从其他智能体导入 | 侧边栏“项目”旁的导入按钮：扫描 Claude Code、Codex、PI-Desktop、Grok、Hermes 的对话，按项目目录分组，可筛选来源、搜索，项目级/对话级勾选和全选；导入后项目出现在侧边栏，对话可接着聊（[MC-ADR-0009](adr/mc-0009-import-from-other-agents.md)） | 源数据只读；重复导入跳过；Codex 按 ID 合并分段、读取真实标题，旧版不完整导入可重建完整副本并保留原会话；对方模型未配置时用本机默认模型；PI-Desktop 无损复制（含工具与压缩检查点）；Grok 导入本地 format 1 文本和工具历史，图片为占位，不带系统注入和加密推理；Hermes 读取本机 state.db（含各 profile），压缩续接合成一个对话 |

补充规则：
- 每个会话只自动加载起始目录的 AGENTS.md；其他工作区的只列出路径，用到时再读。
- 上游 `primaryPath` 字段保留，只作内部兼容，不在界面上表示主次。
- 远程项目首版不纳入 R1。
- 已有项目不再自动建资料目录（2026-10-19 改），保持为简单项目，需要时在工作台手动“转为模板项目”。

### 5.1.1 工作区说明（R10）

| 编号 | 内容 | 规则 | 通过标准 |

| R10 | 工作区说明 | 每个工作区一句说明，存放在资料目录根下的 `workspaces.md`，每个工作区一节，标题为工作区文件夹名（同名时用路径区分）；界面可编辑，也可在任何编辑器里改 | 项目页显示说明；启动会话时，给模型的工作区列表带上各工作区说明；界面编辑只改对应一节，其他内容原样保留；文件缺失或某节缺失时视为没有说明，不报错 |

## 6 任务状态与异常

建议状态：待办 → 进行中 → 待验收 → 已完成；可转为阻塞或取消，验收不通过回到待办。停止／失败不等于完成，保留已有产物并进入阻塞。

用户可在普通聊天中继续自由使用 Agent；资料确认门槛只适用于“从项目任务启动”的管理流程，不额外限制普通对话。

关联资料变化后标出受影响的任务。运行中的任务继续记录原依据（开始时的内容哈希），不自动切换新版本；下次执行重新核对。已完成任务保留历史验收，不因新版本出现自动变成未完成。

## 7 首版不新增的范围

多人云同步、组织权限、复杂排期和依赖图、跨项目自动调度、全量知识库检索、完整在线文档编辑器、“把项目另存为模板”。记忆、会话待办及现有插件等直接复用；多目录项目按 R1 调整为不分主次。

## 8 质量和验收目标

- 数据：资料文件仍由用户持有；解除关联不删除原文件；外部修改不被静默覆盖。
- 权限：项目资料不升级成系统指令；跨根目录和 worktree 访问遵守既有授权。
- 可追溯：每次任务执行能查到资料清单、当时的内容哈希与确认时间（R7.1）、会话、产物与验收结果。能证明“用的是哪一版”，但不保存可恢复的原文副本；需要原文时看版本库或会话记录。
- 体验：键盘可操作，状态有文字说明，找不到文件时有修复入口。
- 模型：版本、服务和登录范围明确列出，通过与未测分开标注。
- 性能：先用真实样例测量；首版资料数量、单份大小和总上下文预算在开发前确定，不能无限注入。

## R11.20 标签按项目合并（2026-11-11 已确认）

P8；V91：标签放不下时，按可用宽度自动合并成项目标签；变宽或关闭到放得下时恢复单个标签。点项目标签展开会话列表，点会话切换，每项可点 × 关闭。无项目会话归入“未分组”；已有页面标签保持独立（当前仅创作，设置等仍从竖栏进入）。多目录项目沿用侧栏归属，项目按首个标签出现顺序排列。

关闭只移除标签，不删除会话、不停止任务，复用相邻标签与分栏焦点规则。保留全部标签入口，项目过多时仍能切换和关闭。横向滚动后的隐藏标签不得覆盖左侧标题栏的原生拖动、双击或相邻按钮；不改变系统的标题栏双击设置。
