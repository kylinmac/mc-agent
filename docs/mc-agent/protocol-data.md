# mc-agent 协议与数据

状态：Fork 方向已确定；本文件是项目管理增量契约草案。依据 [MC-ADR-0002](adr/mc-0002-fork-pi-desktop.md)，删除旧版自建 thread/start、turn/start 等协议要求，继承上游现有消息与会话机制。

## 1 继承接口

上游已有项目组、记忆、会话、待办、产物与运行时接口。源码核对到的 Host 方法包括 project.groups.list、project.group.create／update／context、project.group.memory.get／set、project.memory.get／set、todos.get、artifacts.list。

这些方法不是新的 mc-agent API 清单。UI 必须走现有 preload IPC 和 Main 路由；不能直接调用 Rust 服务或把模型输入当可信调用身份。

正式实现前同时核对 shared 类型、IPC 注册、Host handler 和测试；分析入口见[源码索引](pi-desktop-analysis.md)。

## 2 拟新增实体

字段是设计草案，不是可直接执行的数据库迁移。

| 实体 | 最小信息 | 不承担的职责 |
|---|---|---|
| 项目管理关联 | 上游项目组 ID、legacy 映射、资料目录路径、模板来源、各工作区、上次起始目录 | 不另造平行的项目列表和权限系统 |
| 模板 | 名称、目录路径、来源（内置／自定义） | 不跟踪已创建项目的后续变化 |
| 资料目录根 | 项目组根上的 `kind: "resources"`，位于 `roots[0]`；缺省值按普通工作区处理 | 不作为工作区展示或移除 |
| 整理计划（R5） | 项目、模板、模型、条目列表（来源 → 目标分类，复制／移动）、审批状态、执行结果 | 不绕过 Plan 审批；不替代会话日志 |
| 资料条目 | 稳定 ID、项目、标题、分类、来源（资料目录扫描／手动登记）、文件定位或 URL、状态、确认哈希、更新时间、revision | 不复制整份正文成另一份可编辑主数据 |
| 项目任务 | 稳定 ID、项目、目标、验收条件、状态、资料引用、revision | 不替代会话内 TodoWrite |
| 执行记录 | 任务、起始目录（资料目录或工作区）、Worker 目标工作区、会话／轮次引用、资料来源与哈希、有限快照、结果、创建状态 | 不替代原始会话日志 |
| 验收记录 | 任务、执行记录、结论、说明、产物引用、确认人及时间 | 不代表工具授权或 Plan 审批 |

本地文件用“资料目录或某个工作区 + 相对路径”定位，不存绝对路径，改名时只需更新资料目录本身；使用前解析真实路径。原工作区和 worktree 的同名文件必须分别记录实际来源。资料目录内的文件分类取一级子目录名。URL 只保存引用，不能用一个 URL 声称已锁定远端内容。

## 3 资料状态与变更

- 草稿：可登记、查看，不作为“已确认依据”自动加入任务。
- 已确认：记录确认时内容哈希与时间；任务启动前重新读取并比对。
- 已废弃：保留历史关系，新的任务启动不默认引用。
- 缺失／已变化：从文件实际状态计算的提示，不覆盖历史确认记录。

需要使用草稿时由用户明确选择，并在启动预览和执行记录中标出未确认。必需资料缺失或变化时先补齐／重新确认；不能静默忽略。大文件拒绝或明确选择片段，不无提示截断。

第一次登记和确认文件不隐式改写文件。外部编辑器仍可修改，下一次打开资料详情和任务启动前都要重新校验。

## 4 启动与幂等

建议每次执行新建一个 Desktop 托管会话，同一任务可关联多次执行。后续是否复用会话由评审决定。

流程：校验任务 revision → 准备执行记录与唯一启动标识 → 核验并读取资料 → 调用既有会话启动 → 回填会话归属 → 接收执行结果。

记录状态区分准备中、已启动、失败或结果未知。数据库与会话启动跨边界，不能假定一次数据库事务可以原子完成全部操作；中途崩溃后按启动标识查询并核对，未确认没有启动前不自动重放。

同一任务首版建议一次只运行一个执行；历史执行独立保留。任务状态：待办、进行中、待验收、已完成、阻塞、取消。上游完成事件只能触发待验收，不能代替用户验收。

## 5 最小业务操作

| 操作 | 输入校验 | 关键失败行为 |
|---|---|---|
| 从模板创建项目 | 名称、模板存在、目标目录可写、工作区路径 | 失败不留下半个项目；目标重名自动加后缀 |
| 编辑模板 | 模板名、目录内容 | 不影响已创建的项目 |
| 项目改名 | 无运行中会话、新名合法、目标目录不存在 | 改写失败回滚目录名；不出现数据库与磁盘不一致 |
| 设置起始目录 | 目录属于该项目 | 项目外目录拒绝 |
| 补建资料目录 | 项目尚无资料目录、目标目录可写 | 失败不改项目组；不动工作区 |
| 模板迁移（R5） | 计划已审批、来源属于本项目、目标在资料目录内 | 未审批不执行；单项失败报告并继续或停止由计划指定，不静默跳过 |
| 派发 Worker | 父会话所属项目、目标工作区属于同一项目 | 跨项目或任意路径拒绝 |
| 登记／更新资料 | 项目归属、定位、分类、revision | 越权或版本冲突拒绝；不改原文件 |
| 确认资料版本 | 可读内容、权限、哈希、大小 | 读取失败不生成虚假确认 |
| 创建／更新任务 | 项目、目标、验收条件、引用存在性 | 不接受另一项目的引用冒充本项目 |
| 启动任务 | 状态、revision、上下文、幂等标识 | 缺资料阻止；重复启动返回已有记录 |
| 提交执行结果 | 可信会话／轮次与任务关联 | 拒绝旧事件改写另一执行结果 |
| 用户验收 | 执行记录、预期 revision、结论 | 无执行证据不自动通过 |
| 解除关联 | 对象和影响预览 | 默认不删除磁盘文件或历史验收 |

实际接口名、参数类型、错误码和事件名在编码前按上游模式补齐。不开另一套公共协议来包一层同样的操作。

## 6 持久化与删除

建议新增元数据由 Rust 数据层持有，沿用上游事务与迁移框架，使用独立命名空间／表以减少与上游版本冲突。物理格式尚待确认。

- 移除资料：取消当前关联；已有执行记录保留来源说明，缺失内容明确显示。
- 移动文件：由用户修复定位并重新核对哈希，不根据文件名自动认定同一资料。
- 删除会话：上游 artifact 索引可能级联消失；项目验收记录保留摘要和已关联路径，不只依赖该索引。
- 归档项目：保留任务与资料。删除项目管理数据要说明影响，不隐式删除工作目录或资料目录。
- 项目改名：资料目录跟着改名，同一事务改写按路径存储的上游数据；历史对话里的旧路径不改。
- 数据损坏／磁盘满：报告保存失败，不宣称已保存，不覆盖可恢复记录。
- 升级：先备份、迁移验证；降级不直接打开更高版本数据。
