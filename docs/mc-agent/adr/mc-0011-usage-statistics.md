# MC-ADR-0011: 用量统计

**Status:** Accepted
**Date:** 2026-10-20
**Deciders:** 产品负责人

## 背景

用户要看各个模型、项目的 token 用量。上游每轮结束都记录了用量（`turns` 表的输入、输出 token 和 `usage_json` 里的缓存读写、推理），并提供按日/周/月汇总的 `stats.getTokenUsageHistory`，但 ADR 0173 去掉了设置里的用量页，交给市场插件 `pi.token-insights`；没有按模型、按项目的分组。

## 决定

1. **host-core 新增 `mcUsage.summary { fromMs, toMs }`**（`crates/host-core/src/mc_usage.rs`）：把时间段内所有结束的轮次（含中途停止、失败的，它们也真实消耗了）按模型（提供商 + 模型）、项目、本地日期、对话聚合（另给每天每个模型的明细，供按模型筛选的按天图），给出输入、输出、缓存读取、缓存写入、推理和轮次；总量沿用上游口径：输入 + 输出 + 缓存读 + 缓存写（推理已含在输出里，只单独展示）。用量为 0 的轮次不计。
2. **设置 → 系统 → 用量**：时间范围（今天、7/30/90 天、全部）；总计、输入、输出（含推理）、缓存读取（输入中来自缓存的比例）、缓存写入；按天柱状图（可选模型：全部模型时按模型分色堆叠，选单个模型时分新消耗与缓存读取两段）；按模型环形占比图与表（同一套模型颜色，超过 7 个的合为“其他模型”）、按项目表（带占比条）；用量最多的 15 个对话，点击打开。
3. **不算费用**：本机模型配置没有单价，先只展示 token。

## 影响

- 改动上游：`rpc/mod.rs`、设置导航（`lib/settings-search.ts`、`features/settings/SettingsPage.tsx`）；新增 `mc_usage.rs`、`features/settings/UsagePage.tsx`、`usage-model.ts`。
- 只统计本应用里的对话；导入的对话没有轮次记录，不计入。
- 上游 Electron 开始在 `session.endTurn` 带用量之前的旧轮次可能是 0。

## 重访条件

- 需要费用估算时，为模型加单价配置。
- 上游恢复自己的用量页时改为跟随。
