# MC-ADR-0003: 多工作区平等与项目资料目录

**Status:** Accepted（方向已确认；实现细节见文末“编码前确定”）
**Date:** 2026-10-14
**Deciders:** 产品负责人

## 背景

上游项目组（ProjectGroup）由一个主目录和若干其他目录组成，主目录是 `roots[0]`，承担默认工作目录、重命名锚点和 legacy 记忆位置（源码确认，见 `crates/host-core/src/db/project_groups.rs`）。前后端分离等项目的各个仓库没有主次，这个模型不贴合。

项目还需要一个固定位置放文档、素材等资料。放进某个工作区只适合单仓库项目，而且 worktree 会复制出内容不同的副本，Agent 改代码时也可能一起改动资料。

上游 Worker 会话（session collaboration）创建时沿用父会话目录（`session_collaboration/mod.rs` 中 `project_path: parent.summary.project_path`），无法派到指定工作区。

## 决定

1. **工作区平等。** 产品界面不再区分主目录和其他目录。项目身份用项目组 ID，不用任何目录路径。
2. **每个项目一个资料目录。** 默认 `~/Documents/mc-agent/projects/<项目名>/`，独立于所有工作区。项目改名时目录跟着改名。
3. **模板。** 创建项目时从 `~/Documents/mc-agent/templates/<模板>/` 复制一次。内置 `software`（requirements / architecture / prototype / reference）和 `blank`；支持在应用里编辑和新增模板。之后改模板不影响已有项目。
4. **分类即目录。** 资料目录的一级子目录就是资料分类，里面的文件自动列出；工作区内的文件和 URL 需要手动登记。
5. **起始目录。** 会话可以从资料目录或任一工作区起步，记住每个项目上次的选择。
6. **统筹与派工。** 主会话在资料目录统筹；Worker 会话可指定同项目的目标工作区启动。每个会话只自动加载自己起始目录的 AGENTS.md，其他工作区只列出路径。
7. **兼容上游数据。** 保留上游 `primaryPath` 字段和 `roots[0]` 校验，不删字段、不重写项目组格式。新增数据放 mc-agent 自己的命名空间。
8. **资料目录进入项目组目录列表（方案 A）。** 资料目录作为项目组的一个根，加 `kind: "resources"` 标记，旧数据没有该字段时按普通工作区处理。资料目录占 `roots[0]`，于是它同时是默认起始目录，上游的路径校验、会话归属和启动上下文直接生效。界面、插件、git 分支显示等处按 `kind` 过滤，不把它当工作区展示。
9. **已有项目自动补建。** 已有项目组和 legacy 项目第一次用到项目管理时，自动用 `blank` 模板建资料目录并插入 `roots[0]`，原工作区顺序保留在其后。不改动任何工作区内容。

## 备选与代价

- **保留主次，只改界面文案**：改动最少，但相对路径、AGENTS.md、Worker 目录仍然偏向主目录，问题没解决。
- **按单/多工作区分类，单工作区资料放仓库内**：两套规则；worktree 副本和提交混入问题仍在。
- **用工作区的公共父目录当项目根**：父目录里可能有无关内容，权限范围被扩大；worktree 隔离无法覆盖多个仓库。
- **删除 `primaryPath` 概念**：需要迁移上游数据，并改动一批上游文件，长期同步成本高。
- **资料目录不进项目组，由 mc-agent 自有表单独校验（方案 B）**：上游数据不动，但工具路径校验、按路径查项目、启动上下文、Main 的可读目录列表都要各自打补丁，漏一处就是权限或归属错误。方案 A 漏改只是界面多显示一个文件夹，所以选 A。

代价：资料目录默认不在 git 里（用户可以自己 `git init`）；改名要同步改写按路径存储的上游数据；Worker 派工需要改 host-core 的会话协作逻辑；资料目录要纳入工具路径校验，属于安全边界变化。

## 影响

- **权限**：资料目录与工作区同等对待，Agent 可直接读写，不弹外部路径授权。资料目录以外的路径仍走原有授权。
- **路径数据**：改名需要改写上游按绝对路径存的字段（`projects.path`、`artifacts.path`、排队附件、定时任务配置、worktree），参照 `crates/host-core/src/data_relocation.rs` 的表清单。
- **会话说明**：启动时给模型的 `Primary root / Additional root` 说明改为“本次起始目录 + 同项目其他目录”。
- **远程项目**：上游远程项目只允许一个目录，首版 R1 不覆盖远程项目。
- **文档**：需求 R1、R5，架构、协议与数据、原型 P0–P2、P4、P6、P7，验收 V21–V28 同步更新。

## 编码前确定

- `kind` 过滤点清单：项目详情目录展示、git 分支、插件工作区 `roots`、编辑项目对话框、移除目录逻辑（资料目录不能被当成工作区移除）。
- legacy 项目补建时，从路径型 legacy ID 转成存储型项目组的迁移步骤和回滚。
- 改名的原子性：先改目录名，再在一个事务里改写路径；任一步失败要回滚目录名。
- Worker 派工参数的权限：目标必须属于同一项目，不能借此访问任意路径。

## 重访条件

上游自己加入同等的多工作区或资料目录能力；远程项目需要资料目录；或者改名改写路径的成本明显超出收益。
