# MC-ADR-0007: 并列对话（分栏）

**Status:** Accepted
**Date:** 2026-10-19
**Deciders:** 产品负责人

## 背景

用户希望像编辑器分栏一样把几个对话竖着并排打开，同时看几个任务的进展；多列时右侧工作面板改到每列对话的下方。

上游的对话区一次只服务一个会话：store 里的 `messages`、`isRunning`、工作面板状态和输入框都跟随 `activeSessionId`。ADR 0137 的保留窗格会把最近 3 个会话的对话挂着，但只有活动会话实时更新，其他会话的事件进入缓存（`cacheBackgroundTranscriptEvent`），切回去时才显示。把 store 改成每个会话各自实时，几乎要重写上游的状态层，以后同步上游冲突很大。

## 决定

1. **焦点列模型（同编辑器分组）。** 最多 3 列，每列一个会话。焦点列就是活动会话：输入框、工作面板、信息栏和所有按会话的操作照旧跟着 `activeSessionId`。其他列是保留窗格，点任意位置即聚焦（切换活动会话；窗格已挂着，不重建）。
2. **非焦点列实时更新。** `cacheBackgroundTranscriptEvent` 更新缓存后，如果该会话在分栏里，同时写入它的保留窗格快照（`recordPaneTranscript`），所以非焦点列也能看到流式输出。分栏里的会话在保留窗格的淘汰中被固定（`retainSessionPane` 的 `pinned`），超过 3 个的上限时也不淘汰。切换项目时上游会清空保留窗格，非焦点列这时自己重新读取对话记录。
3. **打开方式。** 标题栏标签拖到对话区，或标签右键“在右侧打开”；对当前显示的会话这样做时，它移到右列，左列放之前看过的另一个会话；列头有关闭按钮，列间分隔线拖动调宽。在标题栏或侧边栏选别的会话时：已在分栏里的会话直接聚焦，其他会话替换焦点列。新建任务还没有会话时，用空列占位。只剩一列时退出分栏。分栏和列宽记在本机（`mc.splitView`），重启后恢复。
4. **工具在列下方。** 分栏时不显示右侧工作面板，焦点列在对话下方停靠同一个工作面板（分区、标签都一样，没有最大化），分隔线拖动高度（`mc.splitDock`）。非焦点列也一直显示输入框：是该会话输入框离开焦点时的静态副本（工具栏、模式、模型都是它自己的，记在本机 `mc.splitComposer`，重启后也一样），点击即聚焦并换成真输入框；对话底部给输入框留的空间按列各自测量（`--composer-dock-height` 设在列上），所以切换焦点时两列都不动，上方列出该会话已打开的工具，点一下聚焦该列并打开对应工具。焦点只在标题栏标签上体现，列本身不加高亮线。浏览器、文件这类原生视图同一时间只在焦点列显示。
5. **信息栏每列一个。** 分栏时每列有自己的信息按钮和信息栏，显示该列会话的数据（上下文、改动、子任务、后台命令按会话分别轮询）；信息按钮放在列头（标题左侧），不压在对话上；停靠还是浮层按该列自己的宽度判断，停靠时只让该列的对话右移，浮层浮在最上层、不改变对话排列。开合状态按会话记住，最后一次的选择作为其他会话的默认。在非焦点列里点压缩、打开改动、子代理、后台命令时先聚焦该列。

## 备选与代价

- **每列都能输入、工具在每列都能用**：需要把 store 改成按会话的实时状态，并让输入框和工作面板按会话实例化，改动和上游冲突都太大。未采用。
- **每列一个独立的渲染进程（WebContentsView）**：隔离彻底，但每列一份应用状态、一份同步，内存与一致性成本高。未采用。

## 影响

- 改动上游：`components/ChatSurface.tsx`（分栏渲染）、`features/app/AppShell.tsx`（分栏时不挂右侧面板）、`components/workpanel/WorkPanel.tsx`（底部停靠形态 `WorkPanelBottomDock`）、`lib/session-panes.ts`（固定分栏窗格）、`stores/runtime/session-runtime.ts`（非焦点列实时）、`test/work-panel.test.mjs`（允许分栏条件）。同步上游时这些地方可能冲突。
- 非焦点列在每个流式增量时都重新渲染，三列同时输出时开销增加。
- 打包后的安装版未测。

## 重访条件

- 上游把会话状态改成按会话实时，或加入自己的分栏时，改为跟随上游。
- 需要多列同时输入时，重新评估按会话的输入框与工作面板。
