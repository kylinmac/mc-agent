# MC-ADR-0005: 工作面板终端与工具栏

**Status:** Accepted
**Date:** 2026-10-19
**Deciders:** 产品负责人

## 背景

上游在 ADR 0108（`docs/adr/0108-remove-built-in-interactive-terminal.md`）里删掉了工作面板的交互式终端：原因是原生模块、终端专用 IPC、打包规则和第二套 shell 生命周期的维护成本，并非终端本身有缺陷。

mc-agent 的场景不同：一个项目有资料目录和多个工作区，用户希望在当前会话的起始目录里直接开终端，而不是切到外部终端再 `cd`。同时工作面板的浏览器每次只能开一个，打开工具要先点“+”进启动页再选，比 Claude Code、Codex 多一步。

## 决定

1. **恢复终端，作为普通的工作面板标签。** 新标签类型 `terminal`，`resource` 是起始目录。每个标签一个登录 shell（`$SHELL -l`），由 Electron Main 的 `TerminalManager`（`electron/main/mc-terminal.ts`）持有；切换标签或关闭面板时 shell 继续运行，重新打开时用回放缓冲恢复输出；关闭标签或退出应用时结束 shell。渲染用 xterm.js。实现取自上游删除前的 D099 代码，改为按标签而不是按目录区分，同一项目可以开多个终端。
2. **起始目录。** 新终端默认在当前会话的起始目录（资料目录或某个工作区）。Main 只在 host-core 登记过的项目目录（项目记录与项目组的本地根）里启动 shell，渲染进程不能借此在任意目录开 shell。远程会话不提供终端。
3. **依赖。** 桌面端重新加入 `node-pty`（1.1.0，与仓库内 `pi-host` 一致，构建时为 Electron 重编译）和 `@xterm/xterm`、`@xterm/addon-fit`。`node-pty` 不打进主进程包，原生文件解包存放，源码目录不打包。上游的打包体积测试相应调整。
4. **工具栏。** 工作面板标题放常用工具图标：终端、浏览器、文件、变更；对应分区打开时图标高亮。终端和浏览器每点一次开一个新标签（浏览器每个标签有自己的页面），文件和变更打开（或展开）各自的分区。“+”启动页去掉；其他插件视图从左侧竖栏下半段（插件扩展区）打开，进入“其他”分区。
5. **配色。** 工作面板标题并入深色标题栏（MC-ADR-0004 的 chrome 色调）。
6. **分区（2026-10-19 补充）。** 面板不再是一条标签栏加一个内容区，而是按工具上下排列的分区：终端、浏览器、文件（文件管理器与对话打开的文件）、变更、其他（子代理、其他插件视图）。分区在有标签时出现，关掉分区即关掉其中所有标签。每个分区有自己的标签条和当前标签，可折叠到只剩标题，拖标题调整上下顺序，拖分区之间的分隔线调整高度。顺序、高度、折叠状态全局保存（localStorage `mc.workPanes`）；标签本身仍是上游按会话保存的列表，分区由它推导，上游打开标签的入口（对话里的文件引用、浏览器预览等）不用改。
7. **多个插件视图同时显示。** 上游 `PluginViewHost` 同一时刻只挂一个原生视图，切换即摘下前一个。分区后浏览器和文件要同时可见，改为可同时挂多个视图、每个视图各自的位置（渲染进程报位置时带上视图 id，不带时按旧行为作用于全部可见视图）；浏览器访客页仍跟随浏览器视图的位置。拖动分区或分隔线时临时隐藏原生视图，否则指针移到原生视图上会丢事件。

## 备选与代价

- **方案 B：不用原生模块**，用 macOS `script` 命令得到伪终端。不增加依赖，但只支持 macOS，窗口尺寸变化不能同步给 shell，全屏程序（vim、top）显示错乱。未采用。
- **沿用上游，不做终端**：零成本，但不满足需求。
- **把终端做成插件**：上游已否决（插件 PTY 权限等于任意执行），这里同样不做。

## 影响

- 安装包增大，构建多一个原生模块；Windows 需要原生构建工具链（mc-agent 首发 macOS）。
- 上游文件的接线：`WorkPanel.tsx`（去掉标签条、拖动排序和“+”，改为工具栏加分区，每个标签的内容由分区渲染）、`plugin-view-host.ts` 与 `plugin-ui-ipc.ts`、`PluginViewTab.tsx`（多视图同时显示）、`AppRail.tsx`（插件视图入口）、`work-panel-tabs.ts`（标签类型）、`register.ts`、`electron.vite.config.ts`、`package.json`；上游的工作面板、插件视图、子代理面板测试中针对单一标签条、“+”启动页、单视图挂载的断言改为检查分区约定。同步上游时这些地方可能冲突。
- 终端是用户自己的 shell，不经过 Agent 的权限审批；Agent 的 Bash 工具不变。

## 重访条件

- 上游重新加入终端，或改动工作面板标签模型时，改为跟随上游实现。
- 需要远程会话终端时，评估复用 `pi-host` 的终端通道。
