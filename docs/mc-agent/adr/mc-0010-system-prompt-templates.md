# MC-ADR-0010: 系统提示词查看与模板

**Status:** Accepted
**Date:** 2026-10-20
**Deciders:** 产品负责人

## 背景

系统提示词此前不可见，只能用 pi 兼容的 `SYSTEM.md`（替换身份）/ `APPEND_SYSTEM.md`（附加）文件定制，项目级优先于全局，没有界面，也不能按模型区分。不同模型适合不同的提示词，不同项目也有各自的要求。

## 决定

1. **查看。** 信息栏“上下文”里的“系统提示”可点开查看本对话实际发送的系统提示词，按段落（基础提示、已激活工具、插件技能、模式与项目上下文）分块、可折叠、可全部复制，并注明命中的模板。查看前先按当前配置重新准备运行时，显示的就是下一条消息会发送的内容。
2. **模板。** 设置新增“系统提示词”页：模板由“身份”（替换默认身份，留空保留）和“附加规则”（追加在基础提示之后、项目指令之前）组成。运行规则、项目 AGENTS.md 和项目记忆始终保留，模板不能替换。
3. **覆盖而非叠加。** 一个对话只用一个模板，整体生效：先看项目规则（对话所在项目的任一目录），再看模型规则（模型名，`*` 通配，不区分大小写；具体型号优先于通配，通配中字面更长的优先），最后全局默认；都不匹配时沿用 `SYSTEM.md` / `APPEND_SYSTEM.md` 文件，再没有就是内置提示。暂不做“项目 + 模型”组合规则和单个对话的临时覆盖。
4. **存储。** 模板和规则作为一个文档存在 host-core 数据库（`kv` 命名空间 `mc.systemPrompts`），`mcPrompts.get / set` 读写并校验（模板 ≤ 50 个、每段 ≤ 64KB、规则 ≤ 200 条、引用的模板必须存在、模式与项目不重复）。Electron main 在启动会话时解析命中的模板，替换 `customSystemPrompt`；配置变化会让运行时在下一条消息前重建。

## 影响

- 改动上游：agent-runtime `runtime.ts`（`systemPromptView`）、`sidecar.ts`（`agent.systemPrompt`）、`runtime/session-launch.ts`（解析模板）、`ipc/project-resources-ipc.ts`、设置导航 `lib/settings-search.ts` 与 `features/settings/SettingsPage.tsx`；新增 `crates/host-core/src/mc_prompts.rs`、`electron/main/mc-system-prompts.ts`、`features/settings/SystemPromptsPage.tsx`、`features/session-info/SystemPromptDialog.tsx`。
- 对话中切换模型可能换模板，那一次请求不能复用提供商的提示缓存。

## 重访条件

- 需要“项目 + 模型”组合或单对话覆盖时再加。
- 上游提供自己的系统提示词管理时改为跟随。

## 修订（2026-10-22）

“项目规则”实际按目录匹配，改称“目录规则”：先匹配会话的起始目录，再匹配项目的其他目录，同一层多条命中取列表靠前的一条；规则指向已删除的模板时跳过。查看器显示命中的目录。仍不按项目 ID 绑定：远程项目、项目改名和目录移动的身份问题留待需要时再定。

新建项目和编辑项目的弹窗里可直接选模板（远程项目没有），存的仍是同一份目录规则：选中模板时，先删掉这个项目各目录上原有的规则，再在主目录上加一条；选“跟随默认”则只删不加，交给模型规则和全局默认。保存前会重新读取配置，所以弹窗打开期间在设置页做的修改不会被覆盖。模板本身仍在“设置 → 系统提示词”里管理。

## 修订（2026-10-23）：新建对话时指定模板

“重访条件”里的单对话覆盖现在做了：新建、还没发过消息的对话，输入框工具栏（权限选择旁）有“系统提示词”下拉，列出设置里的全部模板，首项“跟随默认”，末项“管理模板”跳设置页。选择存在这个对话上，优先级最高：对话选择 > 目录规则 > 模型规则 > 全局默认。

| 项 | 决定 |
|---|---|
| 存储 | host-core `kv` 命名空间 `mc.sessionPrompt`，键为对话 ID，值 `{ templateId }`；`mcPrompts.sessionGet / sessionSet` 读写，写入时校验对话和模板都存在；删除对话时一并清除 |
| 生效 | `session-launch.ts` 启动时先读对话的选择，再交给 `resolvePromptTemplate`（`match.kind = "session"`）；读取失败按“没选”处理，不阻止启动 |
| 模板被删 | 选择作废，回到目录／模型／全局规则，不报错 |
| 可选时机 | 对话没有任何消息时才显示选择器；发出第一条消息后隐藏，之后只能在系统提示查看器里看命中的模板（显示“本对话指定”） |
| 范围 | 仅本机对话；远程对话不显示。分叉出的对话不继承选择（跟随默认规则） |

## 修订（2026-10-28）：追加提示词

第 3 条“覆盖而非叠加”只管模板。另加一类“追加提示词”，只追加、不替换：

| 项 | 决定 |
|---|---|
| 存储 | 同一文档 `mc.systemPrompts` 新增 `appendPrompts: [{ id, name, text, enabled }]`；旧文档没有该字段时按空列表读，模板和规则行为不变 |
| 生效 | 每个启用且有内容的追加提示词都生效，按列表顺序接在命中模板的附加规则之后；没有命中模板时接在 `APPEND_SYSTEM.md` 之后。仍在项目 AGENTS.md 和记忆之前，属于系统提示词，不改用户消息 |
| 范围 | 只有全局开关；目录、模型、对话规则和对话选择器都不能选它（host-core 校验拒绝引用） |
| 校验 | 与模板合计 ≤ 50 条、id 不与模板重复、名称 1–80 字、正文 ≤ 64KB |
| 界面 | 设置 → 系统提示词新增“追加提示词”一节：开关、上下移动、编辑、删除；系统提示查看器显示“追加：A、B” |
| 改动 | `crates/host-core/src/mc_prompts.rs`、`electron/main/mc-system-prompts.ts`、`runtime/session-launch.ts`、`ipc/mc-session-insight-ipc.ts`、`packages/shared` 类型、`SystemPromptsPage.tsx`、`SystemPromptDialog.tsx`；不改 agent-runtime |

按目录或模型启用追加提示词留待需要时再加。
