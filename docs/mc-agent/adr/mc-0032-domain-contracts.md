# MC-ADR-0032 按功能归属维护跨进程契约

已确定，2026-11-22。补充 [Fork 决策](mc-0002-fork-pi-desktop.md)。

## 背景

主会话和子代理各自解释工具结果，导致同一条 MCP 记录在恢复后内容不同。桌面导入的公开类型也散落在扫描器与界面里。过去为便于合并上游而保留这些实现，让维护者改同一条规则时需要找到多个入口。

## 决定

| 归属 | 约定 | 已落地的例子 |
|---|---|---|
| 进程间数据 | TypeScript 生产方与消费方引用同一份公开类型。发送方构造公开对象，执行方继续校验输入 | Preload 与窗口共用 `DesktopPreloadBridge`。会话、模型配置、技能和 MCP 导入共用各自的传输类型。会话来源文件与模型密钥留在 Main |
| 请求生命周期 | 在调用开始时取得本次使用的宿主、sidecar 和扫描结果。切换实例后，新调用取得新实例 | 批量导入被另一次扫描或 IPC 打断时，剩余条目仍交给原宿主。重新注册 IPC 后需要重新扫描 |
| 数据与执行 | 状态规则归实际写入者。总路由处理协议生命周期，功能模块负责参数和领域错误 | Rust 的 `rpc/capability_rpc.rs` 处理技能和 MCP，`rpc/settings_rpc.rs` 处理偏好。导入停用的 MCP 时由宿主先保存停用状态，再发布定义 |
| Agent 上下文 | 同一种工具结果使用同一个内容解析器。执行入口负责授权与工具元数据 | `agent-runtime/src/tool-result-content.ts` 提供实时与恢复入口。主会话和子代理都能恢复 MCP 资源、链接和图片 |
| 依赖方向 | Renderer 和浏览器侧公共代码只能依赖可在浏览器执行的接口。无头 Host 与运行时包独立于桌面壳 | `pnpm check:architecture` 检查可静态识别的模块引用、工作树内新增文件及现有大小预算 |

## 桌面功能依赖

`src/features/<功能>/` 拥有该功能的组件与私有状态。其他功能直接使用它的根级公开模块。嵌套目录供所属功能内部使用；`features/app/` 作为桌面壳可直接装配它所需的功能。功能之间的直接静态依赖保持无环。

按实际复用者决定位置。跨页面的可视控件放在 `src/components/`，可独立调用的规则放在 `src/lib/`，订阅和加载状态放在 `src/hooks/`。这些共享规则、hook 和 store 不能依赖具体功能。新增跨进程能力沿现有 Preload → Main → Rust 或 Node 所有者传递。插件继续通过既有贡献点接入。

从根目录运行 `pnpm check:architecture`。报错会给出越界的源码引用或成环的功能名。用户路径、各层所有者和遗留集中点见[功能架构审查](../architecture-review-2026-11-22.md)。

## 交付与取舍

可以直接重构继承的文件。先选一条能独立操作和验证的用户路径，查明由谁写数据，再移动代码。跨进程变化同时验证两端；修复公共规则还要覆盖复用它的入口。保留已有协议名、合法输入和稳定 ID，修复会丢失偏好的非法输入时记录兼容行为。

静态依赖检查覆盖导入、再导出、字面量动态导入和 `require`。运行时权限仍由各宿主执行。存量大文件按下一次功能修改逐段迁出，现有 Rust 例外和文件预算继续生效。与上游合并时按实际冲突处理。审查范围、验证入口和下一批候选见[本轮架构审查](../architecture-review-2026-11-22.md)。
