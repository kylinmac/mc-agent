# MC-ADR-0022: 继承对话上下文的子代理（fork）

**Status:** Accepted
**Date:** 2026-10-26
**Deciders:** 产品负责人

## 背景

`Task` 启动的子代理都从零开始（上游 ADR 0062）：父代理必须把背景、已读过的文件、用户给过的约束全部写进 `task`。对话越长，这份简报越长，也越容易漏。只有“同样的背景，分头做两件事”时这个成本最明显。

worktree 隔离上游已经有了（ADR 0329）：隔离会话里能写文件的子代理有自己的 worktree，结束后自动合并回来。这一项不需要再做。

## 决定

1. **`Task` 加可选参数 `fork: true`。** 子代理以父代理当前的模型上下文开始，再收到 `task`。简报前加一段说明：它是这段对话的分叉，只做这一件事，最后给父代理一份报告。
2. **上下文怎么截。** 只带用户、助手和工具结果三类消息；父代理正在调用 `Task` 的那条助手消息（及其后同批工具的结果）没有完整结果，切掉。超过子代理预算时，按恢复子代理时的规则（ADR 0299 §7）先丢最早的工具调用和结果。
3. **用父代理的模型。** fork 固定使用当前会话的模型，与 `model`、`resume` 同时出现时报错，避免把一段对话交给上下文窗口和格式都不同的模型。
4. **工具描述**说明什么时候用 fork：子代理需要这段对话已经确立的东西、而复述很长时。

## 影响

- 新增 `packages/agent-runtime/src/mc-subagent-fork.ts`（含测试）；`runtime.ts` 的 `Task` 工具（参数、描述、校验、种子消息各一处）；`delegation-history.ts` 导出已有的截断函数。
- fork 的子代理一开始就带着整段上下文，单次请求更大，费用更高；描述里要求只在复述成本高时使用。
- 之后用 `resume` 继续一个 fork 出来的子代理时，只回放它自己的记录，不再带父对话。
- 未用真实模型验证模型会在合适时机选择 fork。

## 重访条件

- 需要让 fork 换模型时，先验证跨模型回放的格式兼容，再放开 `model`。
