# MC-ADR-0024: 记忆的分类、索引与回顾

**Status:** Accepted
**Date:** 2026-10-26
**Deciders:** 产品负责人

## 背景

项目记忆（MC-ADR-0019）只靠用户手写和 Agent 在对话中途调用 `Remember`，整份注入每次会话，没有来源、不会整理，也没有跨项目的个人偏好。Claude Code 的做法是：一条记忆一个条目、分类型、只加载一行一条的索引、正文按需读，写之前先查重更新，并有专门的整理。

## 决定

1. **条目多几个可选字段**：`kind`（`user` 关于用户 / `feedback` 做法与纠正 / `project` 项目约定 / `reference` 外部资源）、`hook`（一句话摘要）、`source`（来源会话、标题、时间）、`pending`（待确认）、`updatedAt`。存储格式仍是 `entries-v1`，旧条目没有这些字段照常可用；host-core 读写时保留它们，渲染系统提示词时跳过待确认的条目。
2. **“关于我”记忆**：跨项目的条目存在数据目录的 `mc-user-memory.json`，由 Electron Main 读写，规则与项目记忆相同；设置里有“记忆”页管理，并放回顾开关。
3. **索引加按需读取**：会话启动时 Main 拼记忆提示词。项目记忆和“关于我”各自在体量小时整段放入；超过阈值（项目 6000 字、关于我 3000 字）只放索引（每条一行：编号、类型、标题、摘要），Agent 用新工具 `Recall { id }` 读正文。没有项目的对话也带“关于我”。
4. **`Remember` 扩展**：多 `kind`、`hook`、`scope`（`project` 默认 / `user`）；不在项目里的对话只能写 `user`。规则仍是只能改删 Agent 自己写的条目。
5. **对话后回顾**：设置开关，默认关闭（会多一次模型调用）。一轮结束且会话闲置 90 秒后、距上次回顾至少有 2 条新的用户消息时，Main 让该会话的运行时复用最后一次请求（命中提示词缓存）加一段回顾指令，得到最多 3 条建议：新增、更新某条、删除某条（更新与删除只针对 Agent 写的条目）。建议存为 `pending`，在记忆面板“待确认”里由用户记下或丢弃；用量记在那一轮上。
6. **整理**：记忆面板的“整理”按钮在项目最近一个本次启动跑过的会话上执行一次以去重、改写过时内容为重点的回顾，结果同样进“待确认”；没有可用会话时提示先在项目里聊一句。
7. **权限**：`Recall` 只读，host-core 列为低风险。

## 影响

- 新增：`packages/shared/src/mc-memory.ts`（字段、索引与提示词拼装）、`packages/agent-runtime/src/mc-memory-review.ts`（回顾指令与解析）、`apps/desktop/electron/main/mc-memory.ts`（关于我存储、注入、回顾调度、`Recall`）、设置页“记忆”。
- 改动上游：host-core 记忆条目读写保留新字段；`runtime.ts`（工具声明、回顾方法）；`project-memory-prompt.ts` 标题改为“Memory”；`session-launch.ts` 记忆拼装；`runtime/plans.ts` 一行转发轮次结束；`ProjectMemoryDialog.tsx`（待确认、类型、整理）。
- 未用真实模型验证回顾质量。

## 重访条件

- 建议质量差、打扰多时，提高触发门槛或改为只在压缩时回顾。
- 需要按相关性检索时，再给 `Recall` 加关键词搜索。
