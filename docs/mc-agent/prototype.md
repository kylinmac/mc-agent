# mc-agent 项目工作台原型

[P11 Windows 左侧标题栏](windows-titlebar.md)：收缩、通知、搜索固定在左侧；保留竖栏小房子，移除顶部 mc-agent 品牌按钮。macOS 保持原样（R11.12；V51；2026-10-23 澄清）。

状态：低保真评审草案，不是可运行页面。继承 PI-Desktop 现有会话、设置、审批和 Work Panel；下面只画新增项目管理入口。对应[需求文档](requirements.md) R1–R9。

## 1 信息结构

| 页面 | 内容 | 需求 |
|---|---|---|
| P0 新建／编辑项目 | 名称、模板、工作区（平等）、资料目录位置 | R1 |
| P1 项目概览 | 目标、待办、阻塞、待验收、近期会话、工作区与资料目录 | R2 R1 |
| P2 项目资料 | 资料目录文件（按一级子目录分类）、手动登记的工作区文件和链接、确认状态、变更提示 | R3 R4 R9 R1 |
| P3 项目任务 | 目标、验收条件、引用资料、执行历史 | R6 |
| P4 启动预览 | 本次项目、起始目录、模型、资料及版本 | R7 R1 |
| P5 任务验收 | 执行结果、产物、验证说明、通过或退回 | R8 |
| P6 模板管理 | 模板列表、目录结构编辑、新增模板 | R1 |
| P7 整理资料 | 选模板和模型 → 新对话直接整理 → 执行结果 | R5 |
| P8 界面外壳 | 左侧竖栏（内置入口／插件预留／设置）、按项目合并的侧边栏、顶部标签栏（对话与页面） | R11 |
| P9 电脑操作（复用扩展与审批） | 扩展页启用内置插件；对话中先列应用、读状态，再批准操作；Windows 无 macOS 授权页，锁屏／高完整性目标提示限制 | R12；V49 |
| 继承界面 | 原对话、工具、审批、设置、停止与排队 | B1–B8 |

项目入口使用已有项目组。点击项目后进入概览还是保留原会话导航，待评审；不静默改变原导航行为。

## 2 主工作台

```text
┌──────────────┬────────────────────────────────────────────┐
│ 项目列表     │ 项目 A    概览 | 资料 | 任务 | 会话           │
│ · 项目 A     ├────────────────────────────────────────────┤
│ · 项目 B     │ 项目目标：［可编辑摘要］                    │
│              │ 待办 3   进行中 1   待验收 2   阻塞 1      │
│ 原有会话入口 │                                            │
│              │ 需要处理                                   │
│              │ · 需求文档已变化              ［核对］     │
│              │ · 登录功能开发完成            ［验收］     │
│              │                                            │
│              │ 最近任务                       ［新建任务］│
│ 设置／扩展   │ 任务名称      状态       关联会话            │
└──────────────┴────────────────────────────────────────────┘
```

数字来自任务状态，不根据模型措辞猜测进度。项目概览不取代正在运行的会话。

## 3 资料目录

```text
项目资料   ~/Documents/mc-agent/projects/项目A  ［在访达中打开］［登记工作区文件］［添加链接］
分类            名称              来源          状态              关联任务
requirements    login.md          资料目录      已确认            登录功能
architecture    overview.md       资料目录      确认后有修改       登录功能
prototype       login.html        资料目录      草稿              —
reference       api.md            backend 工作区 已确认            登录功能
reference       设计稿链接         链接          未保存本地快照     —

选中资料：打开原文件 | 查看关联 | 确认当前版本 | 解除关联（仅手动登记的）
```

分类就是资料目录的一级子目录，由创建时的模板决定。资料目录里的文件自动出现；工作区里的文件和链接要手动登记并选分类。

确认是一项明确用户操作。打开、登记、确认与允许 Agent 执行是不同动作。文件缺失显示修复路径；解除关联提示“不删除原文件”。

## 3.1 新建项目与模板

```text
新建项目
名称      ［项目A                ］
模板      (•) software   ( ) blank   ( ) client-delivery     ［管理模板］
工作区    ~/code/project-a-web       说明［前端，React + Vite      ］［移除］
          ~/code/project-a-server    说明［后端 Rust API           ］［移除］
          ［添加工作区］
资料目录  ~/Documents/mc-agent/projects/项目A   （创建后随项目改名）
                                                   ［取消］［创建］
```

工作区列表没有“主”标记。说明写入资料目录的 `workspaces.md`（R10），也可以在访达里直接改该文件。模板管理（P6）可编辑模板的目录结构和起始文件，改动只影响之后新建的项目。

## 3.2 整理资料（R5）

```text
整理资料                                   项目A
目标模板   (•) software   ( ) 当前模板（只整理不换）
模型       ［选择模型 ▾］
来源       ☑ ~/code/project-a-web   ☑ ~/code/project-a-server   ☑ 资料目录
                                              ［AI 整理］
→ 新对话中直接执行，先列出将做的事：
来源                               目标                     方式
project-a-web/docs/需求说明.md      requirements/INDEX.md    登记
project-a-server/docs/api.md       reference/INDEX.md       登记
资料目录/旧文档/架构.md              architecture/            移动
（无原型文档）                      prototype/               起草
```

不另设审批，用户在对话中查看或停止（2026-10-15 调整）。工作区文档只登记不复制；移动只在资料目录内部。

## 4 任务与启动预览

任务详情：标题 → 目标 → 验收条件 → 引用资料 → 执行历史 → ［开始执行］。

点击开始后显示：
- 项目与起始目录：资料目录或某个工作区，默认上次选择；是否使用 worktree。
- 派给 Worker 时，显示每个 Worker 的目标工作区。
- 模型与原有权限模式。
- 必需／可选资料，确认状态、实际读取版本、未选入的条目。
- ［返回修改］与［确认并启动］。

必需资料缺失、确认后变化或超限时显示原因与修复入口，不能在角落提示后照常执行。URL 不声称已经读取正文。

## 5 结果与验收

```text
任务：登录功能                    状态：待验收
本次依据：需求.md 的确认版本［查看］
执行会话：［打开］
产物：［相关文件］
验证：［实际测试或人工检查记录］
尚未完成：［剩余问题／无］

［退回待办并填写原因］                 ［确认验收通过］
```

Agent 自述与真实验证分开展示。无结果证据时不自动通过。文件已被删除时保留原记录并显示缺失。

## 6 评审走查

| 情况 | 界面必须表达 |
|---|---|
| 空项目 | 登记已有资料或创建任务的入口 |
| 文件外部修改 | 确认版本已变化，哪些任务受影响 |
| 工作目录切换 | 当前任务仍属于原项目，不跟着界面选择变化 |
| 项目改名 | 资料目录同步改名；有运行中会话时说明为何不能改；失败时提示已回滚 |
| 移除一个工作区 | 项目和资料目录不受影响，只少一个工作区 |
| 模板被修改 | 已有项目不变 |
| 已有项目首次打开 | 保持简单项目，工作台提供“转为模板项目” |
| 整理计划执行中途失败 | 已完成的项和失败项分别列出，不回报为全部成功 |
| 停止／失败 | 继承上游状态，任务阻塞，保留已产生结果 |
| 启动过程中崩溃 | 启动状态待核实，不重复发起 |
| 重启应用 | 任务、资料和执行关联恢复 |
| 用户不接受结果 | 记录原因并退回，保留本次历史 |

已确认（2026-10-14）：点开项目默认进概览，会话列表作为其中一个标签页；验收条件必填，可由 AI 起草；采用人工验收闭环；资料分类由模板决定。P3–P5 属于第二阶段。

## P10 Windows 安装与更新（R15；V50）

首次安装：暗色单页（应用标识、介绍、安装位置、主按钮）→ 同页安装状态 → 完成并打开。背景、文字层次、圆角和按钮与应用设计语言一致，不使用传统多步骤向导作为主要入口。
日常更新：发现新版 → 后台下载进度 → 重启并更新 → 原目录自动替换并启动。失败沿用错误提示和重试入口。
